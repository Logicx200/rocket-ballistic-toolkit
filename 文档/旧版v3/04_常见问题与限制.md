## 1. 安装与启动

cd F:\DeepSeek工作区\火箭弹道工具箱_v3.0
$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
python -m app.main --env

### 1.4 中文乱码

## 2. demo 跑不通 / 跑得慢

### 2.1 内置示例一跑就报"某个步骤失败"

先分辨是**崩溃**还是**自检不通过**：

| 现象 | 含义 | 处理 |
|---|---|---|
| 步骤名后标「失败」且日志有 Python 堆栈 | 真崩溃（一般是数据/环境问题） | 把日志末尾 80 行发给维护者；先试 `--no-invert --modules export,report` 缩小范围 |
| 只有「交付自检」失败 | 成果已生成，是 QC 判据没过 | 看 `report\qc_report.json` 里 `ok=false` 的项；按提示修数据或提高反演预算 |
| 「预测落区」「残骸类型校正」「T0 精化」失败 | 自动步骤失败，主流程通常继续 | 看后续"仿真与数据契约"是否 OK；OK 则结果仍可用（残骸类型未校正时按第一遍初值继续） |
| 「天空轨迹」失败 / 自检不过 | **v3.2.3 起掠射观测点（低仰角、地形先挡住）不会再误报**；仍失败时看日志里的 `[INFO] 地形遮挡角…` 与"几何最大高度角…落在可见区间之外"说明，以及观测点坐标是否合理 | 先确认坐标与 DEM（粗 DEM 下结论只宜定性，见 4.2/4.7） |
| 未启用模块显示「（未启用，跳过）」 | 正常，不是失败 | 需要该产物就回到「运行选项」勾上 |

### 2.2 反演要多久？为什么有时快有时慢

实测（本机，Windows + Python 3.11，示例任务）：

| 环节 | 耗时 |
|---|---|
| 环境/配置构建 | <1 s |
| 残骸类型校正（先试算一次） | 0.4–0.6 s |
| T0 精化（首次试算） | 0.3–0.7 s |
| DEM 扫描 | 0.1–0.7 s |
| **参数反演（示例自动预算 25 次）** | **约 47–51 s** |
| 参数反演（20×10 精细预算，真实 CZ-6A 任务实测） | 约 160 s |
| 仿真与数据契约 | 0.4–0.7 s |
| 发射窗口 | <0.1 s |
| 天空轨迹（详细+主图，每观测点） | 5–9 s（5 个观测点约 10–12 s；含清理旧产物） |
| 出现方位判读图 | 4–9 s |
| 全国最大高度角地图 | 7–18 s |
| 三维 KMZ/KML | 0.1–0.4 s |
| 报告 / 交付自检 | 0.2–0.4 s |
| **内置示例全流程** | **约 70 s** |

影响因素 / 加速办法：

- 反演预算（自动 < 精细）是最大头；「快速」约 30 次仿真；
- 全国地图与天空图各占 10–20 s，可关掉；
- 没有落区也没有参考轨道时，反演会直接跳过（很快）；
- 任务越复杂（多级/助推/多区），反演越慢；
- Windows 下反演**默认串行**（并行启动开销大于收益），别指望 `--jobs 8` 一定更快。

### 2.3 提示「无法确定起飞时刻 T0」/「无法确定发射场」

| 提示 | 原因 | 处理 |
|---|---|---|
| 无法确定起飞时刻 T0 | T0 留空且没有可推断的航警（或 T0 文字无法解析） | 填 T0（`2026-11-18T22:50:00Z` 最稳），或粘贴带 B)/C) 的航警 |
| 无法确定发射场 | 工位名没匹配上内置库，也没给坐标 | 用内置名（`太原 LC-9`、`酒泉 921`），或选「自定义坐标」填经纬度/海拔 |
| 纬度超出 ±90°（疑似经纬度写反） | 把经度当纬度填了 | 坐标顺序是「纬度, 经度」：北京 = `39.9, 116.4` |
| 配置构建失败 | 输入字段类型不对（如把数字写成文字） | 用界面输入或检查任务 JSON |

退出码约定：`0`=成功；`1`=有步骤失败；`2`=输入/配置错误（会打印 `[错误] ...`，无堆栈）。

### 2.4 同一个工作区重复计算：会覆盖还是新建（v3.2.3）

程序会先检查目标成果目录里是否已有上次成果（命中 `config.json`、`运行日志.txt`、`sim\trajectory.csv`、`sim\落点与射程.csv`、`report\qc_report.json`、`report\弹道仿真报告.md` 任一即算）：

| 场景 | 行为 |
|---|---|
| GUI「开始计算」 | 弹窗三选一：**是=覆盖**（复用该目录，同类文件会覆盖/清理旧文件）、**否=新建**（自动建 `<目录>_2`，旧成果保留）、**取消=不计算**；选择写入状态栏与运行日志 |
| 命令行（默认） | 自动新建 `<目录>_2`，打印：`[提示] 本次自动新建工作区：…\xxx_2（如需覆盖旧成果请加 --overwrite）`（**该提示只在控制台输出，不写入 `运行日志.txt`**） |
| 命令行加 `--overwrite` | 复用原目录并打印 `[提示] 覆盖模式：复用已有工作区 …`（实测连跑两次不会产生 `_3`） |
| 目录存在但没有成果（空目录/只放了任务 JSON） | 直接复用，不弹窗 |

> 实测（本机）：同一目录连跑两次 → 第二次生成 `r4_dup_2`；加 `--overwrite` 再跑 → 复用 `r4_dup`，无 `_3`。
> 想保留旧结果又不想改名：先「保存任务」/复制整个成果目录，再覆盖。

## 3. 结果不对 / 落点不在区内

### 3.1 先分清四种"不在区内"

| CSV 里的显示 | 含义 |
|---|---|
| `zone_id` 有值、`inside_zone=false`、`dist_to_boundary_km=1.2` | 落点算出来了，但在航警多边形外 1.2 km → 反演没收敛或参数不对 |
| `zone_id` 为空、`inside_zone=false`、`nearest_zone_id` 有值、`nearest_dist_km=228.14` | 该残骸有**类型匹配**的航警区，但落点在区外 228 km → 模型与任务差得多（v3.2.3 新增列） |
| `zone_id` 与 `nearest_zone_id` 都为空、`inside_zone=false` | 该残骸**没有对应类型的航警区**（例如末级入轨不落区、或本次任务没给该级航警）→ 可能正常 |
| `dist_to_boundary_km` 为空 | 同上（没有可判定的区） |

> 说明：`nearest_zone_id`/`nearest_dist_km` 只在**残骸对象类型匹配**的航警区里找最近的一个；没有匹配类型的区时为空，这是正常情况，QC 也允许为空。

### 3.2 落点在区内但离边界很近（<1 km）

反演目标是"入区且尽量留 10 km 裕度"，但预算小时会停在边界附近。处理：

1. 反演预算改「精细」重跑；
2. 检查航警多边形是否抄错（哪怕一个顶点错 0.1° 也会让边界偏十几公里）；
3. 检查 `stage_hint` 对不对（一级区不要标成整流罩）；
4. 检查参考轨道是否与方位角矛盾（数据体检里 dogleg 提示）。

### 3.3 所有落点都在同一侧偏 10–100 km

常见原因（按概率）：

1. **方位角偏差**：体检里方位角是"自动推断/低"（无落区、由轨道反算）→ 提供落区或手填目标轨道/方位；
2. **T0 偏了几分钟**：落点时刻与航警窗口对不上，窗口计算也会报"无可行窗口"；
3. **箭型质量/推力估值偏差大**：换箭型/用 `vehicle_overrides` 覆盖；
4. **数值口径混用**：反演用了 legacy、导出用 accurate（或反之）→ 统一口径重跑。

### 3.4 入轨根数异常（e 大、近地点为负）

程序会在 `sim\入轨根数.json` 写 `warning` 字段，并在报告 §2.1 置顶提示：

> 注意：入轨根数异常：近地点 -786 km（<100 km），实际未正常入轨。常见原因：箭型质量/推力估值偏差、末级关机过早或制导参数未反演。

常见原因：箭型参数缺失（通用模板）、反演未启用、末级关机设置不合理、参考轨道与射向矛盾。这时**落点/窗口仍可能合理，但"入轨"结论不能用**。

### 3.5 报告里"与参考轨道相比倾角差 -2.4°"正常吗

参考轨道是软约束（权重 20/度），落区是硬约束（20/km）。两者矛盾时程序优先保落区，倾角差几度可能是正常折中，也可能是数据矛盾。判断方法：看体检里 dogleg 是否被启用、"参考轨道"来源是用户还是推断。**推断的参考轨道差 1–3° 属正常量级，差 5° 以上要怀疑数据。**

### 3.6 提示「反演未收敛 / 已回退标称参数」怎么办

v3.2.3 起，反演结束会做**收敛判定**：如果"最优目标"相对"标称目标"改善不明显（最优 > 标称的 60% 且 >200），就判定**未收敛**，程序会**自动回退到标称参数**，并在日志/报告 §2.2 警示：

```
[invert] 标称目标 10962.759 → 最优目标 9496.261；收敛判定=否（落区约束可能与本任务不匹配）
[警告] 反演未显著改善（最优 9496.3 vs 标称 10962.8）：已**回退标称参数**，落点仍可能不在区内，请核对航警/箭型参数
```

> **注意**：本次反演未收敛（最优目标 9496），程序已**回退到标称参数**，上表仅为反演器给出的候选值。落点可能仍在危险区外，请核对航警残骸类型/多边形或改用与任务匹配的箭型参数。

这不是程序崩溃，而是"这次反演不可信，程序主动保住了标称结果"。按下面顺序排查：

| 步骤 | 做什么 | 怎么看 |
|---|---|---|
| 1 | 先量化"差多远" | 看 `sim\落点与射程.csv`：`zone_id` 为空但 `nearest_zone_id`/`nearest_dist_km` 有值 → 落点离最近航警区还有多少 km；每半罩/每级都看一遍 |
| 2 | 核对航警原文 | 编号、B)/C)、多边形顶点（`[lat, lon]` 顺序）、FIR 是否抄错；两条整流罩区是否分给了左右半罩 |
| 3 | 核对残骸类型 | 看日志「残骸类型校正（两遍法）」的"旧类型 → 新类型（对象，距离）"。若匹配距离 >500 km 或明显不合理，**在 GUI 航警页双击该行手动改类型**（手工指定优先，程序不再覆盖） |
| 4 | 换更匹配的箭型参数 | 同型号不同批次/构型差异大时，用「精细化」反演预算，或在任务 JSON 用 `vehicle_overrides` 覆盖质量/推力/关机时刻 |
| 5 | 确认参考轨道 | 体检里参考轨道是"推断/低"时，它会与落区约束打架；建议显式填目标轨道高度/倾角（有公开资料时） |
| 6 | 接受"模型不匹配"的结论 | 如果资料都对、箭型也对，落点仍差 200+ km，说明这次任务的真实弹道/构型与内置参数不同——**报告里应写成"模型与任务不匹配、落点不可用"**，不要强行解读 |

**真实案例（CZ-6A，2026-11-29 任务）**：两段航警距发射场约 1213/1286 km，模型标称弹道的整流罩落点只有约 963 km（差 250–323 km）；反演 1020 次仿真只能把目标从 10962 降到 9496（87%）→ 判定未收敛并回退。报告里正确写法是"本次反演未收敛，落点仅供量级参考"，而不是"落点应在某区"。

### 3.7 参考轨道置信度为什么是「中」？为什么自动启用了末级平面机动（dogleg）

v3.2.3 起，"只给航警、不给目标轨道"时，倾角由方位角反算后会和箭型 `typical_orbits` 比较：

| 差值 `|Δi|` | 采用值 | 置信度 | 体检 note |
|---|---|---|---|---|
| ≤ 5° | 该典型轨道的高度+倾角 | **中** | "相差 X°（≤5°），采用典型轨道值" |
| 5–8° | 保留反算倾角 | 低 | "倾角由方位角…反算" |
| > 8° | 不采用典型倾角 | 低 | 追加"未采用典型值" |

实测（真实 CZ-6A，`real_cz6a_20261129_auto.json`）：

```
[自动推断/中] 参考轨道 = h=700 km, i=98.200°  # 方位角 193.7° 反算倾角 100.61°，与箭型典型轨道「SSO 700 km」的 98.20° 相差 2.4°（≤5°），采用典型轨道值（高度 700 km）
[自动推断/中] 末级平面机动目标倾角 = 98.20°  # 参考轨道倾角 98.20° 与由方位角 193.7° 估算的 100.61° 相差 2.4°（2°~12°），判定需要末级平面修正（dogleg），已设 i_target_deg
```

两条连带影响（用户最常问）：

1. **参考倾角与方位角反算倾角差 ≥2°（且 ≤12°）时，程序会自动启用 dogleg**，事件表出现"末级平面修正(dogleg)开始"——这是按规则做的平面修正，不是故障；报告里入轨/落点结论要打折。
2. 置信度从"低"升到"中"后，**自动反演不再走"低置信放宽边界"分支**，搜索区间更紧（示例：`t_p` 区间 130–150 s，含标称 133.7 s）。如果反演反而更难收敛，多半是典型轨道与真实任务差得多——**请直接填写目标轨道高度/倾角**。

### 3.8 「残骸类型已按预测落点校正」的告警怎么读（v3.2.3）

两遍法校正后如果出现下面两类告警，说明航警区与本次任务的模型落点对不上，**必须人工核对**：

| 告警原文（实测 CZ-2F） | 含义 | 处理 |
|---|---|---|
| `航警 A6094/26 原文残骸类型为「一级」，程序按预测落点改判为「整流罩 / fairing_R」（距区中心 72 km）；如与航警原文不符，请在「航警」页手动指定类型，或核对该区是否属于本任务` | 原文类型与模型预测冲突 | 以官方航警原文/任务资料为准；双击「航警」页该行手动指定类型（手工指定优先） |
| `航警 A6095/26 与最近预测落点 fairing_L 相距 1189 km（>500 km）：该区可能不属于本任务（另一发任务/另一类残骸），建议核对航警原文或删除该区` | 这个区离本次模型落点太远，可能不是本任务的区 | 核对航警编号/日期/多边形；确认不属于本任务就删掉该区，否则反演会被它拉偏 |

- 两类告警都会写进 `config._v3.warnings`，并在报告「**数据体检**」章节原文出现（可搜"不属于本任务"/"原文残骸类型"）；
- 它们**不会**让程序崩溃或让 KML/地图失败，但会显著影响反演与落区判定——看到就按上表核对，不要当普通提示忽略。

## 4. 天空轨迹

### 4.1 天空轨迹没生成

| 检查 | 说明 |
|---|---|
| 有没有观测点？ | 没有观测点时 **sky/appear 自动跳过**；全国最大高度角地图照常生成（见 4.6） |
| 勾了「天空轨迹」模块吗？ | 运行选项里确认 |
| 观测点坐标解析成功了吗？ | 体检里应有"观测点 xxx"一行；解析失败会警告"已忽略" |
| 观测点会不会在发射场背面/太远？ | 目标可能全程在地平线下（无可见事件），图仍会出但无"首次出现" |

### 4.2 首次出现时刻偏早/偏晚（DEM 缺失）

- 无 SRTM 瓦片时程序用内嵌粗 DEM（约 2 km），首次出现时刻误差可达**数十秒**；
- 日志会打印："未取得 SRTM 1″ 瓦片：天空轨迹将使用内嵌粗 DEM…不能用于正式结论"；
- `sky\sky_summary.json` 里 `observers.<id>.horizon_deg` 是遮挡角范围，粗 DEM 下通常只有 ±几度、近场剖面失真；
- 想要正式结论：补 SRTM 瓦片后重算（见第 6 节）。
- **掠射观测点（离弹道很远、仰角接近 0°）**：v3.2.3 起最大高度角按"可见时段内"统计，地形先挡住几何最大值时只给 INFO、不再判自检失败（见 4.7）。

### 4.3 天空轨迹出现"仰角 −31°"或明显离谱

**观测点经纬度写反了**（纬度 > 90 或与发射场相距上万公里）。程序当前会拦截 |纬度|>90 的输入并报错；若是坐标数值都在范围内但写反了（如北京写成 116.4, 39.9），会得到"目标全程在地平线下"的结论——看到负的首次出现仰角就是信号。重新按「纬度, 经度」填写。

### 4.4 `sky_summary.json` 里太阳相关字段怎么看

| 字段 | 含义 |
|---|---|
| `observers.<id>.solar.observer_sun_el_t0_deg` | T0 时观测点的太阳高度角（负=日落/曙光方向） |
| `...solar.twilight_state_t0` | 晨昏状态文字（民用晨昏等） |
| `...solar.rocket_sunlit_fraction` | 火箭被阳光照亮的时长占比 |
| `...solar.first_sunlit` | 首次进入光照的时刻与高度 |
| `...first_appearance / max_elevation / last_visible` | 几何可见的首次/最大/消失（`t_utc`、`az_deg`、`el_deg`） |
| `...dusk_condition`、`...twilight_visible` | 暮光可见性判据（阈值与是否满足） |

> 注意：太阳高度用的字段是 `observer_sun_el_t0_deg`（不是 `el_deg`），写脚本/二次开发时别取错。

### 4.5 主图和"出现方位地形判读图"有什么区别

- `天空轨迹_*.png`：目标在天球上的轨迹（方位-仰角）+ 可见/阳光标注；
- `出现方位地形示意图_*.png`：**观测点近场地形剖面**，告诉你"这个方位上地形多高、要多少仰角以上才看得见"，用于解释"为什么首次出现是那一刻"。

### 4.6 没有填观测点会怎样（v3.2.3）

| 模块 | 没填观测点时 |
|---|---|
| 天空轨迹、出现方位地形图 | **跳过**（这两个确实需要观测点） |
| **全国最大高度角地图** | **照常生成**！它给的是"全国任意地点对火箭的几何可见性上界"，与某个具体观测点无关；只是图上/表里**不叠加"指定观测点"标注** |
| 地图自带的 `.md` | 会写"本任务未指定观测点；图与统计均为'全国任意地点对火箭的几何可见性上界'…"，关键地点表用"发射点（未指定观测点，代理）" |
| 体检/日志 | 提示："未提供观测点：天空轨迹与出现方位图将被跳过；全国最大高度角地图照常生成（不叠加观测点标注）" |

实测（`tests\qa\missions\no_observer_map.json`）：map 步骤 **[完成] 7.6 s**、PNG **2175×1559**、地图自检 25/25；QC「全国地图 PNG 存在且宽度 ≥1600 px」**PASS**；`config._v3.modules` 里 `sky=false, appear=false, map=true`。

> 想看"某个观测点"的天空轨迹与地图标注：在「观测点」页加一个点后重算即可。

### 4.7 为什么"最大高度角"是可见时段内的？日志里的"几何最大高度角"是什么（v3.2.3）

v3.2.3 起，"最大高度角"默认按**可见时段内**统计：

- 只统计目标真正可见（未被地形/地球曲率遮挡）的时段；
- 全弹道的**几何最大值**单独保留，必要时给 INFO（格式：`[INFO] 几何最大高度角 +X° @ T+… 落在可见区间之外（该时刻已被地形遮挡）`）——这是**正常物理现象**，不是失败；
- `sky\sky_summary.json` 里 `max_elevation` 是可见时段内口径（附 `basis` / `geometric_max_masked` / `geom_max_el_deg` / `geom_max_t_met_s`），`max_elevation_geometric` 是全弹道几何口径。

**为什么旧版会误报**：观测点离弹道很远、视线低仰角"掠射"时，地形遮挡角会先于几何最大值挡住火箭，几何最大值出现在可见终止之后；旧版拿几何最大值要求"首次出现 ≤ 最大 ≤ 消失"，就误判"自检失败"。

**实测（同一 CZ-2F 任务、广州 obs5，两种 DEM 模式都正常）**：

| DEM 模式 | 实测 |
|---|---|
| **有 SRTM 1″ 瓦片**（用户任务原机，遮挡角最高 1.07°） | 出现掠射可见窗口 490.59–506.43 s：`最大高度角（可见时段内）0.48° @ T+506.43 s` + INFO `几何最大高度角 +0.62° @ T+536.50 s 落在可见区间之外（该时刻已被地形遮挡）`；天空自检全部通过、QC 26/26 |
| **本机粗 DEM**（无 SRTM，内嵌 ~2 km 网格） | 广州**全程几何不可见**：`basis=geometric_only(no_visible_interval)`、`first/last=null`、只给几何参考值 0.33°；同样正常，粗 DEM 不宜做正式结论 |

口径统一为："**最大高度角按可见时段内统计；若全程不可见则 `basis=geometric_only`，只给几何参考值**"。差异只来自 DEM 精度，不是程序行为不一致。

**什么时候才真的要修**：

| 情况 | 处理 |
|---|---|
| 日志出现"几何最大…落在可见区间之外" | 正常，无需处理（报告里引用"可见时段内"值即可） |
| 首次出现/消失为 `null`（全程不可见） | 正常（观测点太远/在地平线下），该点没有可见性结论 |
| 首次出现时刻明显偏早/偏晚 | 检查 DEM 是否粗网格、观测点坐标/高程是否填错（见 4.2/4.3） |
| 天空步骤真的报"失败"（不是 INFO） | 看日志末尾的 `[INFO] 地形遮挡角…`、观测点坐标；必要时 `--modules sky` 单独重跑定位 |

### 4.8 多个观测点时，天空图的文件名怎么认（v3.2.3）

| 场景 | 文件名 |
|---|---|
| 多个观测点 | `天空轨迹_<地点名>_<纬度>N_<经度>E.png/.csv/.md`，如 `天空轨迹_广州_23.13N_113.26E.png`；全景 `天空轨迹_全景_<第一个观测点地点名>_<纬度>N_<经度>E.png`；太阳地影 `太阳地影示意_<第一个观测点地点名>_<纬度>N_<经度>E.png`；出现方位地形 `出现方位地形示意图_<第一个观测点地点名>_<纬度>N_<经度>E.png`；重名自动加 `_2`（后三者只对第一个观测点生成） |
| **单个**观测点 | 沿用 `天空轨迹_<obs_id>`（如 `天空轨迹_obspoint`）；全景 `天空轨迹_全景.png`；太阳地影 `太阳地影示意_<obs_id>.png` |
| 哪里能查到实际文件名 | `sky_summary.json` 每个观测点的 `label`/`file_tag`/`outputs`；技术报告「天空轨迹」章节按 `outputs` 列出**实际文件** |

> 这样同一个目录里 5 个观测点的图一眼能分清是哪；不会再出现 `_obs1_obs1` 这种重复后缀。旧产物会在每次运行 sky 前自动清理。

## 5. 全国最大高度角地图

### 5.1 地图一片空白 / 只有中国轮廓

全国地图的网格默认是中国范围（72–136°E / 15–55°N），国界/省界底图也是中国数据。**非中国任务**（如卡纳维拉尔角、种子岛）时：

- 网格会自动外扩（发射场在网格边缘外时），但没有对应国界底图，图会"空白/错位"；
- 处理：关掉「全国最大高度角地图」模块，或自行为 `engine\common\boundaries.py`/`plot_map.py` 提供对应区域底图（属于二次开发）。

### 5.2 地图为什么这么慢 / 网格多大

中国范围 0.2° 网格 = 321×201 = 64,521 格，逐格计算最大仰角 + 晨昏线，12–18 s 属正常。`map\网格.csv` 有 6 万多行，Excel 打开会慢，建议用 pandas/脚本处理。

### 5.3 地图上看不到火箭 / 最大值 89.9° 在海上

最大值出现在**星下点附近**（火箭正头顶），所以可能落在海上或边界附近；图上还叠加了晨昏线与"阳光可见"版，注意看图例区分"几何可见"与"阳光照亮下可见"。

### 5.4 白天发射的任务，地图自检会误报吗（v3.2.3）

不会。`map\统计.json` 的自检项「航警窗口跨越中国晨昏带」在**全程昼侧**的任务里也会 PASS，详情写"（统计域全程昼侧，无晨昏线穿越）"；只有"既不是全昼、也不是全夜、又没有晨昏线穿越"这类真正的异常才会 FAIL。实测真实 CZ-6A 白天任务（T0 太阳高度 +30.5°）：该项 PASS，地图自检 25/25 通过。

## 6. 离线补 DEM 瓦片

### 6.1 需要哪些瓦片

程序按任务自动算：发射场、观测点（半径 `dem_radius_km`，默认 200 km）、航警区覆盖的 1°×1° 瓦片。日志会列出缺哪些，如 `缺 5 片瓦片（示例 ['N29E109', …]）`。

### 6.2 从哪来、怎么放

- 来源：SRTM 1″（AWS Open Data `elevation-tiles-prod/skadi`，公有领域），文件名类似 `N37E112.hgt.gz`；
- 放置：把 `*.hgt.gz` 放 `dem\gz\`，或解压成 `*.hgt` 放 `dem\hgt\`；
- 目录：开发版 `engine\data\dem\`；便携版 `%LOCALAPPDATA%\RocketKit\dem\`（或以 `settings.json` 的 `dem_dir` 为准）；
- 瓦片级幂等：重复放不会重复处理；程序启动时会"扫描历史 DEM 瓦片"自动导入。

### 6.3 勾「允许 DEM 在线补全」为什么没下载

- 该勾选只影响运行期；离线/断网/网络慢（实测国内访问 AWS 可能只有十几 KB/s）时会失败并回退粗 DEM；
- 无网络环境不要勾，避免等待超时；直接用已有瓦片或粗 DEM。

## 7. KML / KMZ 在 Google Earth 里显示异常

### 7.1 落点是红色/其他颜色图标是什么意思（v3.2.3）

KML 里的残骸落点按"与航警区的关系"分三种图标，**颜色本身就是结论**：

| 图标/样式 | 含义 | 名称标注示例 |
|---|---|---|
| 绿色（`#impactIn`） | 落在对应航警区**内** | `整流罩左半残骸落点（A5898/26 区内）` |
| **红色**（`#impactOut`） | 落在对应航警区**外**，名称里给出**最近航警区与距边界距离** | `整流罩左半残骸落点（A6105/26 区外，距边界 228.14 km）` |
| 灰/其他（`#impactOther`） | 没有**类型匹配**的航警区（如末级入轨不落区、本次任务没给该级航警） | `助推器1残骸落点（无对应航警区）` |

- 点击落点弹出的气泡里还会写"是否在 xx 危险区内 / 距危险区多边形边界 / 备注"；
- `viz\校验_KML.json` 的 `checks` 会如实记录 `impacts_in_zones`、`n_impacts_checked`、`n_impacts_outside`，另有 `warnings` 如"存在落在危险区外的残骸落点（2/2 区外）"；
- **落点在区外属数据/模型问题，KML 步骤本身仍算 OK（只告警）**；落区是否正确由交付自检与报告 §3 判定，不要凭 KML 图标下结论。

### 7.2 其他显示异常

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 KMZ 打不开/图标丢失 | 打开的是 `.kml` 且图标是相对路径 | 优先用 **`.kmz`**（自包含，图标已打包）；或把 `engine\viz\files\` 一起拷走 |
| 图形样式变简单、颜色丢失 | 在 GE 里"另存到我的地点"会剥离 Document 级 Style | 不要另存；用「临时位置」或 NetworkLink 方式查看 |
| 文件大、GE 卡 | 弹道/残骸轨迹点很多（CZ-6A 示例 KML 约 640 KB、54 个 Placemark、8 条 track） | 正常；关闭不需要的图层，或只看 KMZ |
| 航警区位置对但时间动画不对 | GE 的时间动画按 UTC；本工具时间轴可能需要手动拖 | 在 GE 里把时间滑块拉满/关闭时间动画 |
| 浏览器打开 KML 没反应 | KML 需要 Google Earth / 支持 KML 的软件 | 装 Google Earth Pro，或改用 QGIS |
| 三维轨迹"太高/太陡" | 高度是真实几何高度，GE 垂直夸张系数默认 1 | 在 GE 里调"垂直夸张"或看 `sim\trajectory.csv` 数值 |

### 7.3 点「打开成果目录 / 技术报告 / KMZ」没反应，或报错 `0xc0000142`

v3.2.3 起"打开"改为逐级降级，**不再弹系统错误框 0xc0000142**：

| 环境 | 程序行为 |
|---|---|
| 正常 Windows | 等同双击：目录用资源管理器打开；报告/文本优先记事本；KMZ 优先 Google Earth；找不到 Google Earth 时**在资源管理器中定位该文件** |
| 企业管控 / 沙箱 / 无桌面权限 | 系统拒绝启动资源管理器时，程序**把路径自动复制到剪贴板**并弹中文提示；你把它粘到「文件资源管理器」地址栏回车即可 |
| 路径已不存在 | 提示"路径不存在"，请回运行页确认工作区是否被移动/删除 |

> 本机实测（正常 Windows）：目录 → "已在资源管理器中打开"；报告 → "已用记事本打开"；KMZ → "已用 Google Earth 打开"，全部成功。
> v3.2.3 验收记录（受限环境/沙箱）：目录 → 提示"路径已复制到剪贴板"，报告与 KMZ 仍可正常打开，全程无 `0xC0000142` 弹窗。日志/状态栏会显示"已在资源管理器中打开""已用记事本打开""路径已复制到剪贴板"等结果。

## 8. 数据来源、精度与限制

### 8.1 数据从哪来

| 类别 | 来源 |
|---|---|
| 箭型/工位/城市/载荷/轨道库 | 公开资料汇编（维基、Orbit Codex、AeroPattern、任务卡等），每条带 `sources` 与 `confidence` |
| 地形 | SRTM 1″（AWS Open Data）/ 内嵌 0.02° 粗 DEM（Mapzen/AWS Terrain Tiles） |
| 底图 | Natural Earth（公有领域） |
| 航警 | **用户提供**（程序不联网检索航警） |
| 大气/引力 | US Standard Atmosphere + EGM 低阶带谐项（v2 引擎） |

### 8.2 哪些数字是"估计值"

- 内置库里 `confidence` 为 **中/低** 的箭型（部分小固体、商业火箭）分级质量/比冲是估值；
- 所有"自动推断"项（T0、方位角、参考轨道、残骸类型）都是经验规则；残骸类型虽有"两遍法"校正，仍建议核对；
- 通用模板（不给箭型）只有量级意义；
- 预测落区只是示意；"反演未收敛回退"则说明这批参数不可信。

### 8.3 本工具**不做**什么

- 不做真实六自由度姿态、风场、发动机调节、分离扰动；
- 不做航警原文核实（以你粘贴的为准）；
- 不做正式轨道确定/预报（只给 SECO 瞬时根数 + 首圈星下点）；
- 不保证与真实发射一致——**它是公开信息分析工具，不是任务仿真软件**。

## 11. 普通用户 10 分钟能跑通吗？

**能，前提是走"载入示例 → 看体检 → 开始计算"这条路**（实测全流程约 70 s）。真正需要 10 分钟以上的地方是"找资料、写自己的任务"（航警原文、T0、箭型、观测点），不是点按钮。

10 分钟检查清单：

- [ ] 0:00 启动程序（首次 2–5 s）；
- [ ] 0:30 点「载入示例」，看任务信息/航警/观测点三页是否自动填好；
- [ ] 1:30 点「⑤ 数据体检 → 生成体检」，能看懂"来源/置信度"两列；
- [ ] 2:30 点「开始计算」，等 1–2 分钟；
- [ ] 5:00 看结果摘要与步骤耗时，点「打开成果目录」「打开技术报告」；
