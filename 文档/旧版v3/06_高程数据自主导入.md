# 06 高程数据自主导入（离线 GeoTIFF / SRTM 瓦片）

> 适用版本：v3.1 起（v3.0 只有"在线下载 SRTM → 粗 DEM 回退"两条路）。
> 面向**没有网络、下载不到 SRTM 瓦片，但手上已有高程数据**的用户。
> 相关代码：
>
> | 文件 | 作用 |
> | --- | --- |
> | `engine/common/geotiff.py` | 最小 GeoTIFF 读取器（classic/BigTIFF、LZW/deflate/PackBits、tfw、nodata） |
> | `app/core/dem_import.py` | 导入管理器：格式识别、复制/引用、`index.json` 登记、覆盖率 |
> | `engine/common/dem.py` | 运行时采样：自定义源优先，未覆盖处回退 SRTM/粗 DEM |
> | `app/core/dem_manager.py` | `prepare()` / `status()` / `dem_mode()` 认识自定义源 |
>
> 相关测试：`tests/test_dem_import.py`（`python tests\test_dem_import.py`）。

---

## 1. 为什么需要这个功能

离线版工具箱原本只有两条路：

1. 在线下载 AWS skadi 的 SRTM 1″ 瓦片（`<TILE>.hgt.gz`）；
2. 没有瓦片时回退内嵌 0.02°（约 2 km）粗 DEM —— 天空图的"首次出现时刻"精度只有 ±数十秒。

如果用户手里有一份更精确的高程数据（例如整个山西省的 WGS84 GeoTIFF，
45670×64942、约 10 m 分辨率、1.32 GB），就应该能**直接导入**并参与计算：

* 观测点/发射场海拔（`observer_dem.json`、数据体检表）；
* 天空轨迹的**地形遮挡角**（`plot_sky` 的 `terrain_block_deg`）；
* 弹道落区地形（`appear` / 地形图）。

不需要先把 GeoTIFF 切成 1°×1° 的 SRTM HGT 瓦片。

## 2. 支持的格式一览

| 格式 | 扩展名 | 处理方式 | 落地位置 | 是否参与计算 |
| --- | --- | --- | --- | --- |
| GeoTIFF | `.tif` `.tiff`（classic TIFF 或 **BigTIFF**） | 校验后登记（默认**引用**原文件，可选复制） | `<dem_dir>/custom/index.json`（+`custom/data/` 副本） | ✅ 点采样/遮挡角（见第 7 节覆盖规则） |
| SRTM 1″ HGT | `.hgt`（3601×3601×2 字节） | 复制（先写 `.part` 再原子替换） | `<dem_dir>/hgt/<TILE>.hgt` | ✅ 走引擎原有 1″ 瓦片路径 |
| SRTM 1″ HGT.GZ | `.hgt.gz` | 解压到 `hgt/`，同时归档到 `gz/` | `<dem_dir>/hgt/<TILE>.hgt` | ✅ 同上 |
| ZIP 压缩包 | `.zip` | 安全列出成员，只取 `.hgt/.hgt.gz/.tif/.tiff`（+`.tfw/.ovr`） | 同上 | ✅ 逐个导入 |
| 目录 | 任意目录 | 递归扫描上述扩展名 | 同上 | ✅ 逐个导入 |

> **3″ 瓦片（1201×1201）不支持**：引擎全链路按 1″（3601×3601）设计，3″ 数据会明确报错，
> 不会"登记了却不参与计算"，避免用户误以为用上了。

## 3. 快速上手

### 3.1 GUI（由 Lead 集成，接口见第 11 节）

数据体检/设置页的"导入高程文件"按钮应调用：

```python

# info = {"ok": n, "failed": [{"path","error"}], "sources": [...], "tiles": [...]}
```

导入后立刻刷新体检表（`dem_manager.status()`），并提示用户：
"自定义高程源已登记：`id=山西WGS84`，范围 lat 34.58–40.74 / lon 110.23–114.56，
分辨率 0.34″，nodata=-32767；点采样将优先使用该数据。"

### 3.2 命令行 / Python

```python
from app.core.dem_manager import DemManager
from app.core.paths import dem_dir, setup_env

setup_env()                                  # 设置 RK_DEM / RK_ENGINE 等环境变量

info = dm.import_dem(r"D:\BaiduNetdiskDownload\山西\山西WGS84.tif")   # 引用模式（推荐）

print(res["mode"])                           # "custom"：所有关键点都被自定义源覆盖
```

只导入 SRTM 瓦片：

```python
dm.import_dem(r"D:\tiles\N37E112.hgt.gz")            # 解压到 <dem_dir>/hgt/N37E112.hgt
dm.import_dem(r"D:\tiles\srtm_pack.zip")             # 批量
dm.import_dem(r"D:\tiles\inbox", copy=True)          # 整个目录（GeoTIFF 会复制一份）
```

### 3.3 引擎侧确认


## 4. GeoTIFF 文件要求（硬性）

### 4.1 坐标系

* **只接受地理坐标（经纬度）**：EPSG:4326，或未标注坐标系但坐标范围在
  lon ∈ [-180, 180]、lat ∈ [-90, 90]；
* 投影坐标系（UTM / WebMercator / CGCS2000 3° 带……）会被**拒绝**并提示：
  "请先转成 WGS84 经纬度 GeoTIFF"；
* 转换命令（需要另装 GDAL/QGIS，工具箱本身不需要）：

```bat
gdalwarp -t_srs EPSG:4326 in.tif wgs84.tif
gdal_translate -co COMPRESS=LZW -co TILED=YES -co BIGTIFF=IF_SAFER wgs84.tif out.tif
```

QGIS：右键图层 → 导出 → 要素另存为 → CRS 选 `EPSG:4326` → 创建选项里压缩 `LZW`。

### 4.2 支持 / 不支持的 TIFF 特性

| 项目 | 支持 | 说明 |
| --- | --- | --- |
| 文件结构 | classic TIFF（magic 42）、**BigTIFF**（magic 43，8 字节偏移） | 山西文件就是 BigTIFF |
| 字节序 | `II`（小端）、`MM`（大端） | 自动识别 |
| 组织方式 | 分块（Tile）与条带（Strip） | 分块更快（按需解压） |
| 压缩 | 1 无、5 LZW、8/32946 deflate(zlib)、32773 PackBits | **不支持 JPEG(7)** |
| 预测器 | 1（无）、2（水平差分，按样本位宽） | 预测器 3（浮点）明确报错 |
| 数据类型 | 8/16/32 位整型、32/64 位浮点 | int16 最常见 |
| 波段 | 单波段优先，多波段取**第 1 波段** | 高程文件几乎都是单波段 |
| 地理参照 | `ModelTransformation`(34264) > `ModelPixelScale`(33550)+`Tiepoint`(33922) > 同名 `.tfw` | `.tfw` 的 C/F 是左上像素**中心**，读取时自动减半像素 |
| nodata | `GDAL_NODATA`(42113) | 命中 nodata → `nan` |
| 金字塔 | 忽略 `.ovr`（只读第一个 IFD） | 不影响正确性，只影响"远场"速度 |

> 工具链里**没有 imagecodecs**，所以 LZW 解压是本项目自己实现的
> （标准库 `zlib` + `struct` + `numpy`）。已用真实 GDAL 产物验证：同一块数据
> 重新编码后与原始 LZW 字节流**逐字节一致**，且相邻块接缝高程差平均 2–4 m。

### 4.3 分辨率与高程基准

* 分辨率 = 像素大小（`res_deg`）。山西文件约 0.0000949°（纬度方向 ≈10.5 m，经度方向随纬度略小）。
* 高程基准沿用 SRTM 口径：**EGM96 正高当椭球高使用**。与 SRTM 数据混用时误差约 −10 ~ −30 m，
  对遮挡角（只看相对高度）影响可忽略；对绝对海拔请在报告中注明。
* 海面/负值：GeoTIFF 里如果是水深（负值），遮挡计算会按 `sea_level_clip` 裁剪到 0（与 SRTM 一致）。

## 5. 两种导入模式：引用 vs 复制

| | 引用（`copy=False`，默认） | 复制（`copy=True`） |
| --- | --- | --- |
| 磁盘占用 | 0 | 原文件大小（1.3 GB 就是 1.3 GB） |
| 导入耗时 | 毫秒级 | 与文件大小成正比（流式复制，带进度回调） |
| 原文件被移动/删除 | 源失效（`status()` 里 `valid=false`，需重新导入） | 不受影响 |
| 适用 | 大文件、本机固定盘、临时任务 | 想长期归档到 `%LOCALAPPDATA%\RocketKit\dem`、或原文件在网络盘/U 盘 |

复制时：

* GeoTIFF → `<dem_dir>/custom/data/<slug>.tif`（重名自动加 `-2`、`-3`）；
* 同名 `.tfw` / `.tif.ovr` 一起复制（保证地理参照和外部金字塔可用）；
* **ZIP 里的 GeoTIFF 一定复制**（zip 解压用的临时目录随后会删除）。

## 6. 数据在哪里：目录结构与 `index.json`

```
<dem_dir>/                         开发态 = engine/data/dem
│                                  冻结态 = %LOCALAPPDATA%\RocketKit\dem
├─ hgt/<TILE>.hgt                  SRTM 1″ 瓦片（含导入的 .hgt/.hgt.gz 解压结果）
├─ gz/<TILE>.hgt.gz                下载/导入的压缩瓦片
├─ cache/<obs_id>.npz              观测点 3″（≈90 m）局部缓存
├─ dem_mode.json                   runner/GUI 读的"本次实际数据模式"
└─ custom/
   ├─ index.json                   自定义高程源登记表（唯一索引）
   └─ data/                        copy=True 时的 GeoTIFF 副本
```

`custom/index.json` 结构（`schema` 固定 `rocketkit.dem_custom.v1`）：

```json
{
 "schema": "rocketkit.dem_custom.v1",
 "updated_utc": "2026-11-26T04:24:46Z",
 "sources": [
  {
   "id": "山西WGS84",
   "kind": "geotiff",
   "name": "山西WGS84",
   "file": "D:\\BaiduNetdiskDownload\\山西\\山西WGS84.tif",
   "original": "D:\\BaiduNetdiskDownload\\山西\\山西WGS84.tif",
   "copied": false,
   "bbox": [34.58382131, 40.74495334, 110.23024069, 114.56301301],
   "res_deg": [0.0000948713, 0.0000948713],
   "width": 45670, "height": 64942, "bands": 1, "dtype": "int16",
   "compression": 5, "compression_name": "lzw", "tiled": true, "big_tiff": true,
   "nodata": -32767.0,
   "crs": "EPSG:4326",
   "size": 1322406077,
   "sidecars": ["D:\\...\\山西WGS84.tfw", "D:\\...\\山西WGS84.tif.ovr"],
   "added_utc": "2026-11-26T04:24:46Z",
   "note": "引用原文件（未复制；移动/删除原文件后需重新导入）"
  }
 ]
}
```

* `bbox` 顺序固定为 **[lat_min, lat_max, lon_min, lon_max]**（与 `dem.py`/报告一致）；
* 索引损坏（手工改坏、拷贝中断）时，导入管理器会把原文件备份为
  `index.json.bad-<时间戳>` 并重建空索引，**不会崩溃**；写索引用 `.part` + 原子替换；
* 同一个文件重复导入是幂等的（更新原记录，不产生重复条目）。

## 7. 引擎如何使用自定义源（优先级与覆盖规则）

### 7.1 点采样 `common.dem.sample()`

```
自定义源（按 index.json 登记顺序，先覆盖先用）
   ↓ 未覆盖 / nodata
SRTM 1″ 瓦片（.hgt）
   ↓ 缺瓦片
内嵌 0.02° 粗 DEM
```

* **输出形状、`method`、`missing`、`void_value` 语义与 v3.0 完全一致**；
* 被自定义源覆盖的点直接出值；未被覆盖的点继续走原有 SRTM/粗 DEM 逻辑；
* 自定义源的 nodata：`void_value` 为 `nan` 时按缺测继续回退；`dem_alt()`（`void_value=0`）
  按 0 m 处理，与 SRTM void 语义一致；
* **没有 `custom/index.json` 时，所有原有函数行为/返回值/模式字符串逐位不变**。

### 7.2 地形遮挡角 `_make_samplers()`

遮挡角要求**同一个源完整覆盖观测点 `dem.horizon_radius_km` 圆的外接矩形**，
否则（例如只导入了山西省、但观测点在省界附近，200 km 圆超出数据范围）会回退到
原有逻辑（3″ 缓存 → 1″ 瓦片 → 粗 DEM），并在日志里说明。

此时：

* `prepare()` 仍可能报 `mode="custom"`（关键点被覆盖、跳过下载），
  但返回值里 `custom_radius_ready=false`，日志会提示"遮挡半径未被完整覆盖"；
* 天空图遮挡角实际走粗 DEM（精度下降），**点采样/海拔仍用自定义源**。

**建议**：

1. 导入的数据范围 ≥ 任务区 + 观测点 `horizon_radius_km`（默认 200 km）；
2. 或者把 `config.dem.horizon_radius_km` 调小到数据范围以内（例如 50 km）；
3. 或者同时保留 SRTM 瓦片（有瓦片时遮挡角优先用瓦片？——不：自定义源优先，
   但**覆盖不完整**时会回退瓦片，所以两者可以互补）。

### 7.3 多源与模式字符串

* 多个自定义源：点采样按登记顺序，先覆盖先用；遮挡角要求**某一个**源单独完整覆盖
  （不做多源拼缝，避免接缝高程不一致导致遮挡角跳变）；
* `last_mode()["mode"]` 新增取值 `"custom"`（另有 `"srtm"/"coarse"/"none"` 保持不变），
  `note` 形如 `geotiff:山西WGS84`（遮挡角）或 `point:山西WGS84`（点采样）；
* `dem_manager.dem_mode()` 同样返回 `"custom"`；
* `dem_mode.json` 里 `"mode": "custom"` 并附 `"custom_sources": [...]`。

## 8. 覆盖率：这份数据够不够用？

```python
from app.core.dem_import import DemImportManager
mgr = DemImportManager(dem_dir())

cov = mgr.coverage([("发射场", 38.5, 112.0), ("观测点A", 37.87, 112.55),
                    ("落点", 39.2, 113.1)])
print(cov["total"])          # {"covered": 3, "total": 3, "ratio": 1.0}
print(cov["sources"])        # 每个源覆盖的点数/比例、bbox、值域
print(cov["points"])         # 每个点是否覆盖、命中的源、采样高程 [m]
```

* **覆盖**按源 bbox 统计；点数不多（≤200）时会额外采样，给出 `has_data`
  （真正取到有效高程的点数，能识别 bbox 内的 nodata 区域）；
* `DemManager.status()["custom_coverage"]` 会带上**最近一次任务关键点**的覆盖率；
* `DemManager.custom_plan(config)` 返回 `ready`（关键点全被覆盖，可跳过下载）
  与 `radius_ready`（遮挡半径也被完整覆盖）两个判据。

## 9. 实测性能参考

测试机：普通办公 CPU（Windows 10，Python 3.11），数据 = 山西 1.32 GB BigTIFF
（45670×64942，int16，LZW，128×128 分块，共 181356 块）。

| 操作 | 实测 | 备注 |
| --- | --- | --- |
| `inspect()`（解析头/标签） | **0.5 ms** | 不读像素、不读 18 万条块偏移 |
| 单点 `sample()`（冷启动） | 1–8 ms | 首次要把该块 LZW 解压（约 2–3 ms/块） |
| 随机 2000 点双线性 | **3.6–3.8 s**（约 1.8–1.9 ms/点） | `tests/test_dem_import.py` 实测 |
| 随机 5000 点双线性 | **8.8 s**（5000 最近邻同为 8.7 s） | 约 5000 个块解码 |
| 相邻块接缝高程差 | 纵向 3.6 m / 横向 2.3 m | 解码正确性的间接验证 |
| 太原（37.87N,112.55E） | 768 m | 与真实地形一致 |
| 五台山（39.08N,113.58E） | 2951 m | 主峰 3061 m 附近 |
| 大同（40.08N,113.30E） | 1031 m | |
| 运城（35.03N,111.00E） | 340 m | |

**地形遮挡角**（90 m 步长、720 方位、5° 抽样测试）：50 km × 72 方位约 5.8 s。
按 200 km 圆估算约 **2–4 分钟/观测点**（需要解压约 10 万个 1 km² 小块）——
这是"不建缓存、直接读原始大文件"的代价。如果追求速度：

1. 先把数据裁剪到任务区（减小文件会显著减少块数）；
2. 调小 `horizon_radius_km`；
3. 保留 SRTM 1″ 瓦片 + 3″ 观测点缓存（覆盖不完整时遮挡角会自动回退瓦片）。

### 9.1 与 SRTM 1″ 瓦片的交叉验证（本机实测）

同一批 34 个随机点（山西境内，SRTM 瓦片已下载区域）分别用两条路径采样：

| 路径 | 说明 |
| --- | --- |
| `common.dem.sample()` | 现有 SRTM 1″ HGT 瓦片（memmap 最近邻） |
| `common.geotiff.GeoTiffSource.sample_many()` | 本模块读 1.32 GB BigTIFF（LZW 解码） |

结果：`GeoTIFF − SRTM` 均值 **−24.2 m**、中位数 −23.5 m、标准差 **8.5 m**、范围 −48 ~ −11 m，
**没有一个点的偏差超过 100 m**。地形起伏形态完全一致（若字节序或地理参照错一个像素，
差异会达到几十米到上百米且随机）。该 ~24 m 的系统差属于**垂直基准/数据源差异**
（SRTM 为 EGM96 正高，该 GeoTIFF 可能为椭球高），对"只看相对高度"的遮挡角影响很小，
但**绝对海拔**（观测点高程）跨源对比时要留意：同一任务内尽量只用一种源。

## 10. 常见问题（错误消息 → 处理）

| 现象/报错 | 原因 | 处理 |
| --- | --- | --- |
| `不支持的 TIFF 压缩方式 7（jpeg）` | 源文件是 JPEG 压缩 | QGIS/GDAL 转 LZW：`gdal_translate -co COMPRESS=LZW` |
| `GeoTIFF 是投影坐标系（32650）…请先转成 WGS84 经纬度` | UTM 等投影坐标 | `gdalwarp -t_srs EPSG:4326 in.tif out.tif` |
| `GeoTIFF 缺少地理参照…` | 既无 GeoTIFF 标签也无 `.tfw` | 用 QGIS 重新导出带地理坐标的 GeoTIFF，或补同名 `.tfw` |
| `不支持带旋转的 GeoTIFF` | 栅格带旋转项 | 用 GDAL 去掉旋转（配准到正北） |
| `文件大小 … 不是 1″ SRTM 瓦片` | 下载不完整 / 不是 3601×3601 | 重新下载；或改用 GeoTIFF |
| `是 3″ 瓦片（1201×1201）；本工具箱只使用 1″` | 数据是 SRTMGL3 | 换 1″（SRTMGL1）或 GeoTIFF |
| `文件名不是合法瓦片名（应为 N37E112 形式）` | `.hgt` 文件名不规范 | 改成 `N37E112.hgt` 再导入 |
| `自定义源 xxx 打不开（…），已跳过` | 引用文件被移动/删除 | `list_sources(valid_only=False)` 看 `error`，重新导入 |
| 索引损坏但程序没崩 | 已自动备份 `index.json.bad-*` | 重新导入即可 |
| 导入后 `mode` 仍是 `coarse` | 关键点不在数据 bbox 内（或落在 nodata 区） | 看 `status()["custom_coverage"]`，换覆盖更全的数据 |
| `mode=custom` 但遮挡角精度没提升 | 数据没覆盖观测点 `horizon_radius_km` 圆 | 见 7.2 节；调小半径或导入更大范围 |

## 13. 集成注意事项（Lead / GUI 必读）

本次改动**没有**碰 `app/gui/**`、`app/core/runner.py`、`app/core/report.py`，
但这两处对 `srtm` 有硬编码，接入 `custom` 模式时需要 Lead 顺手改一行：

1. **`app/core/runner.py::_step_dem`**（约 332–338 行）：

   ```python
   if info.get("mode") != "srtm":                      # ← custom 也会命中，会误报"未取得 SRTM 瓦片"
       self._sink("warn", "未取得 SRTM 1″ 瓦片：天空轨迹将使用内嵌粗 DEM…")
   cfg["_v3"]["dem_mode"] = ("srtm" if info.get("observer_ready") else info.get("mode"))
   #                          ^ custom 模式下 observer_ready=True → 报告会写成 srtm（与事实不符）
   ```

   建议改为：

   ```python
   if info.get("mode") not in ("srtm", "custom"):
       self._sink("warn", "未取得 SRTM 1″ 瓦片：天空轨迹将使用内嵌粗 DEM…")
   cfg["_v3"]["dem_mode"] = info.get("mode") if info.get("mode") == "custom" else (
       "srtm" if info.get("observer_ready") else info.get("mode"))
   ```

2. **`app/core/report.py`**（约 337–340、415、477 行）：把 `dem_mode not in ("srtm", "1")`
   一律当成"精度不足"。自定义 GeoTIFF 往往比 SRTM 更精细，建议把 `"custom"`
   也纳入"精细"分支，并在"数据来源"一行写 `自定义高程 GeoTIFF（用户导入）`。

3. **GUI 数据体检页**建议展示：

   ```
   自定义高程源：山西WGS84  45670×64942 int16 LZW(BigTIFF)
     范围 lat 34.5838..40.7450, lon 110.2302..114.5630   分辨率 0.34″
     nodata=-32767   引用: D:\BaiduNetdiskDownload\山西\山西WGS84.tif
     本任务覆盖率 3/3（100%）   遮挡半径覆盖: 是
   ```

   数据来源：`dm.status()["custom_sources"]`、`dm.status()["custom_coverage"]`、
   `dm.custom_plan(config)["ready"] / ["radius_ready"]`。

4. **进度回调**：`import_dem(..., progress=cb)` 的 `cb` 兼容
   `cb(done, total, note)` / `cb(fraction)` 两种签名，可直接接到现有进度条；
   1.3 GB 文件复制时建议用复制模式并在后台线程执行（引用模式是毫秒级，无需线程）。
