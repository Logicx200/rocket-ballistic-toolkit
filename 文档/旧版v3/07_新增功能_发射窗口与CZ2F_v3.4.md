# v3.4 新增功能：轨道发射窗口 / CZ-2F 交会对接 / 离线高程导入

适用版本：v3.4（2026-11-26）。本文件说明三项新增能力的原理、输入输出、命令与限制。
源码态已生效；`build\dist` 内的 exe 仍是旧版，需重新打包后才包含本版功能。

## 1. 轨道发射窗口（`engine/scripts/window.py`）

### 1.1 为什么需要

v3.0 的「发射窗口」只由航警 B)/C) 与残骸到达时刻反推，回答的是"残骸不跑出禁区的
T0 区间"，不是轨道意义上的发射窗口。v3.4 增加**轨道平面窗口**：对已知目标轨道
（RAAN / 太阳同步 LTAN）或已知交会目标（空间站），求满足
`|RAAN_achieved(T0) − RAAN_target(T0)| ≤ 容差` 的时间窗。

### 1.2 原理

1. 从 `sim/trajectory.csv` 的入轨点（SECO）取**相对地球速度**（CSV 的 `vx_ecef` 等
   已是惯性速度减去 ω×r 的相对速度），加回 `ω×r` 得到惯性速度，转到 TEME
   （与工具箱上升段 ECI 同口径）。
2. 目标倾角由入轨点方位角反解：以目标倾角为约束，二分求出会形成该倾角的入轨方位角
   （含地球自转影响；允许 180°~360° 的西南射向）。
3. 目标 RAAN：
   - **空间站**：官方 OEM/TLE 在入轨时刻的 RAAN（J2 章动/岁差已由数据源体现）；
   - **显式 RAAN**：`RAAN0 + J2 长期漂移 × (t − epoch)`；
   - **太阳同步 LTAN**：`RAAN = α_sun + 15°·(LTAN − 12)`；
   - 只给高度/倾角的低轨任务：轨道面可取任意方向，**不构成平面窗口约束**，程序会明确
     说明而不是编造窗口。
4. 对 T0 扫描（默认 ±48 h、20 s 步长），求 |ΔRAAN| ≤ 容差（默认 0.2°）的连续区间；
   用二分细化窗口边界、黄金分割求窗口中心（最小 |ΔRAAN|）。
5. 输出与航警时窗相交信息，保留 v3.0 的 `model_window` / `practical_window` 字段，
   新增 `orbit_window`（`report/发射窗口计算.json`）。

### 1.3 输出（节选）

```json
  "available": true, "mode": "auto", "tolerance_deg": 0.2,
  "target": {"kind": "station|raan|ltan|free", "...": "..."},

               "duration_s": 93, "d_raan_deg": 0.0,
```

### 1.4 配置字段

```json

  "mode": "auto",            // auto / raan / ltan / free
  "tolerance_deg": 0.2,
  "search_hours": 48,
```

## 2. CZ-2F 空间站交会对接（单独成一支）

### 2.1 数据源（`engine/common/station.py`）

优先级：

1. 用户导入的 OEM 文本/文件（`config.station.oem_path` / OEM 文本）；
2. 用户粘贴的 TLE（`config.station.tle`）；
3. **内置官方 CMSE/BACC OEM 精密星历快照**（`app/data/station/CSS_OEM_20261120...dat`，
   2026-11-20 ~ 2026-11-27，4 min 步长）；
4. 内置 CelesTrak TLE 快照（历元 2026-11-19，超过 20 天会警告沿迹相位误差）；
5. 在线拉取（仅 `--allow-network` / GUI 勾选「允许在线」时）：CMSE 公告页 ZIP →
   解压 OEM；CelesTrak TLE；
6. 全部失败 → 中文错误提示，指引导入 TLE/OEM。

坐标系：OEM 为 `EME2000`，读取时用 IAU 1976 岁差 + IAU 1980 章动主项转到 TEME
（与工具箱上升段 ECI 同口径；实测与 astropy TEME 差约 40 m）。TLE 由 SGP4 直接给 TEME。

### 2.2 流水线新增步骤

| 步骤 | 脚本 | 产物 |
|---|---|---|
| `station` 空间站轨道准备 | `engine/scripts/station_track.py` | `sim/空间站轨道.json`、`sim/空间站星下点.csv`（星下点、过境、T0/入轨时刻根数） |
| `docking` 入轨+对接 | `engine/scripts/rendezvous.py` | `sim/交会对接.json`、`sim/交会对接_时序.csv` |

只有 `mission.profile == "cz2f"` 且 `station.enabled=true` 时执行；其他任务自动跳过。

### 2.3 交会模型

1. **入轨**：取 3-DOF 弹道 SECO 状态（约 200 km）。
2. **平面匹配**：按空间站倾角反解入轨方位角，确保与空间站共面。
3. **相位调整**：计算入轨时空间站与飞船的纬度幅角差；选择一个近圆"相位轨道"，绕 k 圈
   使转移点火时目标领先 `180° − n_st·T_H`（200→380 km 约 3.6°）；ΔV 由活力公式给出。
4. **Hohmann 转移**：半圈椭圆到空间站高度；按实际递推状态与到达时刻的空间站半径自适应
   求脉冲，消除 J2 漂移导致的拱点偏差。
5. **圆化**：按实际半径与速度圆化。
6. **最终逼近**：二体 Lambert 两脉冲，从当前位置到 `final_s` 后的空间站位置；末端位置
   精确匹配，再做速度匹配（对接制动）。
7. **自洽性**：前 4 步用二体+J2 RK4 递推，最后一段用二体 Lambert（几何闭合）。报告给出
   末端模型残差、总 ΔV、总时长与可行性。

默认参数（`config.station.rendezvous`，可在 GUI「⑤ 空间站」修改）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `target_time_h` | 6.5 | 期望交会总时长（软目标） |
| `max_phasing_h` | 13.0 | 相位段最大时长 |
| `dv_budget_mps` | 300 | 总 ΔV 预算（含末段） |
| `final_approach_s` | 1800 | 最终逼近时长 |
| `final_approach_dv_mps` | 10 | 末段修正上限（后备模型用） |
| `max_phasing_orbits` | 10 | 相位段最多圈数 |

### 2.4 CZ-2F 结果包含什么

- `sim/入轨根数.json`：入轨根数（原有）；
- `sim/空间站轨道.json`：数据源、覆盖、T0/入轨时刻空间站根数、星下点、过境；
- `sim/交会对接.json`：入轨段、相位方案、Hohmann、时间线、对接时刻、总 ΔV、可行性；
- `sim/交会对接_时序.csv`：入轨→相位→转移→圆化→逼近→对接逐事件时序；
- 报告第 4.3 节（交会窗口）与第 5 章（入轨+对接）；
- 结果摘要新增「空间站」「交会对接」两行。

## 3. 离线高程自主导入

详见 [`06_高程数据自主导入.md`](06_高程数据自主导入.md)。要点：

- 支持 **WGS84 经纬度 GeoTIFF**（`.tif/.tiff`，BigTIFF/classic、LZW/deflate/PackBits、
  16/32 位、tile/strip、含 `.tfw` 或内嵌地理参照）与 **SRTM HGT/HGT.GZ/ZIP**；
- 无第三方 GDAL/imagecodecs 依赖，自带 LZW 解码器；1.2 GB 山西 GeoTIFF 只读所需 tile；
- 导入方式：GUI「④ 运行选项 → 导入高程文件」、菜单「设置 → 导入离线高程文件」、
  命令行 `python -m app.main --import-dem <文件或目录>`；
- 登记表 `<DEM目录>\custom\index.json`；默认**引用原文件**（不复制），复制模式可选；
- 计算时自定义源优先于在线/本地 SRTM；点采样/观测点高程走自定义源；地形遮挡要求
  自定义源完整覆盖观测点 `horizon_radius_km` 外接矩形，否则回退 SRTM/粗 DEM；
- 报告 §11 会列出已导入的自定义高程源，§9 注明垂直基准差异。

## 4. 天空轨迹/出现方位图的「台阶」与弹道叠加（v3.4.1）

### 4.1 台阶是什么

`天空轨迹` 主图底部的**棕色地形遮挡线**、`出现方位地形图` 中的**灰色规范判据**，
都按「方位 0.5°（出现方位图 1°）× 距离 90 m」采样 DEM 计算每个方位的最高仰角。
在观测点近场，一个 SRTM 像元（1″≈30 m，缓存 3″≈90 m）在 90 m 距离处可占据数度方位角：

- **水平平台**：同一道近场山脊/同一个 DEM 像元在若干相邻方位上都是最高点；
- **垂直跳变**：射线离开该像元/山脊，最高点切换到下一处地形；
- 因此看起来像台阶，但它是 **DEM 采样量化**，不是弹道跳变、不是数值不稳定。

`出现方位地形图` 同时画了两条线：

- **稳健天空线（棕色实线，判读用）**：忽略最近 200 m，地形高程 5 点（300 m）中值去噪；
- **规范判据（灰色虚线，对照用）**：sky 模块实际可见性口径（近场 1″ 精采样、90 m 步长），
  对近场单像元噪声更敏感，台阶更明显。

本次 CZ-6A 例：规范判据在 300–306° 维持 4.45°、306–319° 跳到 3.81°，就是近场像元/山脊切换；
稳健天空线同一扇区只有 0.85–2.89°。首次出现按 sky 判据为 3.81°，若按稳健线则更晚一点，
报告中的 ±3 s 不确定度已覆盖这一差异。

### 4.2 出现方位图上的弹道

v3.4.1 起，`出现方位地形示意图_obs1.png` 增加：

- **(a) 主图**：外圈按时间着色的**弹道方位弧**（青→黄→红=时间），内侧浅色**扫描扇**
  （每约 15 s 一条方位射线），星/圆/方块分别标首次出现、最大高度角、消失方位；
- **(e) 右下小图**：真实**弹道方位–高度角曲线**（颜色=时间）叠加稳健天空线，
  可直接看出「火箭仰角何时高于地形线、从哪个方位露出」；
- `出现方位地形_数据.json` 新增 `trajectory` 字段（CSV、点数、时间/方位范围）。

注意：主图是 30 km 局部地形图，火箭在 160 km 以外，**地面投影放不进这张图**；
所以主图叠加的是「观测方向（方位角）随时间」，不是弹道的真实地面位置。

## 6. 已知限制

- 轨道窗口假设不同 T0 时弹道相对地球固连、整条轨迹随地球自转旋转；不是六自由度制导。
- 空间站 OEM 只覆盖 2026-11-20 ~ 2026-11-27；其他日期需导入新 OEM/TLE 或在线拉取。
- TLE 回退在历元数天后沿迹相位误差可达数度，交会窗口/对接时刻只具量级意义。
- 交会模型为共面圆轨道 + 三次脉冲 + 末段 Lambert；未计大气、姿控、测控、真实制导与
  交会走廊约束，**不是飞行程序**。
- 最终逼近用二体 Lambert 保证几何闭合，因此末端残差显示为 0；实际 J2/摄动残差需
  相对导航修正（报告已注明）。
- 离线高程遮挡要求完整覆盖半径外接矩形；部分覆盖时点采样仍用自定义源，但遮挡角回退。
- 未重新打包 exe（按用户要求暂不打包）。
