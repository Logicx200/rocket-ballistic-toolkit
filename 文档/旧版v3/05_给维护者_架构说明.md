## 2. 数据流（一次任务的完整链路）

```
GUI 输入（6 页） / 任务.json / --demo
        │  MissionInput（app/core/model.py）
        ▼
build_config()（app/core/config_build.py）
  ├─ infer.py 补全：箭型→工位→航警→T0→方位角→参考轨道→箭型参数/制导→观测点→网格/DEM
  ├─ autoplan.py 生成 inversion（参数+边界+DE 预算）与 mc
  ├─ 写 config.json + config_initial.json
  └─ 写数据体检：config.mission._provenance（[Resolution...]）
        │  config.json（+ _v3 元数据：modules/notams_mode/needs_refine_t0/warnings）
        ▼
PipelineRunner.run()（app/core/runner.py）
  ├─ 每步 os.environ["RK_ROOT"]=workdir，runpy 调 engine/scripts/*.py
  ├─ 自动步骤（顺序）：predict（无航警→试算→生成提示落区）
  │                  → stagehint（残骸类型两遍法校正：试算→按预测落点最近匹配，写 object_hint）
  │                  → t0refine（试算→按窗口校核 T0）
  ├─ invert 步骤内含"收敛守卫"：最优 vs 标称目标比较，未收敛则 runner 回退标称参数
  └─ 顺序：dem → invert → export → window → sky → appear → map → mc → kml → report → qc
        │
        ▼
工作区产物：config.json / sim\ / sky\ / map\ / viz\ / report\ / uncertainty\ / 运行日志.txt
        │
        └─ qc 之后再刷一次 report（让 §7 带自检结论）
```

关键设计：

- **单向下游只读 `sim\`**：除 export 外，其它脚本都不重新仿真，保证"同一份数据出一套成果"；
- **推断与计算分离**：`infer.py` 是纯函数（不启动仿真），`config_build` 只组装；真正的率定在 `invert.py`；
- **两遍法**：航警残骸类型第一遍按距离猜（标记 `_hint_inferred`），第二遍用试算落点反查（`_step_stagehint`），结果写 `stage_hint`+`object_hint`；用户手工指定的类型不进第二遍；
- **收敛守卫**：`invert.py` 写 `converged/nominal_objective`，`runner` 在未收敛时把 config 回退到 `config_initial` 的标称参数并记 `_v3.inversion.reverted=true`；
- **每步失败不整体中止**：只有 `export` 是 essential（失败即终止），其它步骤失败标记后继续；
- **KML 区外落点只告警**：`make_kml_refstyle.py` 用 `#impactOut/#impactOther` 区分并写 `校验_KML.json` 的 `n_impacts_outside`，落区判定交给 qc；
- **参考轨道置信度（v3.2.3）**：`infer_reference_orbit` 把方位角反算倾角与箭型 `typical_orbits` 比对——|Δi|≤5° 采用典型轨道（置信度中、可能触发 dogleg 且 autoplan 不再走"低置信放宽"分支）；5–8° 保留反算值（低）；>8° 不采用典型倾角（低）。改阈值要同步 03 文档与 `CHANGELOG_v3.md`；
- **观测点不是 map 的前置条件（v3.2.3）**：`config_build` 只关 `sky/appear`，`map` 保留；`plot_map.py` 对空观测点全套兜底（用发射场作代理、说明与统计注明"未指定观测点"）；
- **打开外部程序（v3.2.3）**：`paths.open_path()` 降级链 = ShellExecuteW → 显式启动（干净环境/绝对路径/尝试脱 Job）→ 失败把路径复制到剪贴板并提示；**不要**在受限环境里再 spawn explorer（会 `0xC0000142`）；
- **天空轨迹最大高度角口径（v3.2.3）**：`plot_sky.py` 默认取**可见时段内**最大值写 `sky_summary.json.observers.<id>.max_elevation`（含 `basis/geometric_max_masked/geom_max_el_deg/geom_max_t_met_s`），全弹道几何值另存 `max_elevation_geometric`；自检只要求可见区间内 first ≤ last，几何最大值落在可见区间外时给 INFO 而不是 FAIL。改天空自检时别再把几何最大值当可见最大值；
- **sky 产物生命周期（v3.2.3）**：每次运行 sky 前清理本目录已知旧产物（旧 PNG/CSV/MD/sky_summary.json），附加图/主图文件名只带一层观测点标识（避免 `_obs1_obs1`）；说明 md 的任务描述必须按 `config.mission` + T0 + 发射点动态生成，**不要写死型号**；
- **多观测点命名（v3.2.3）**：`plot_sky.py` 写 `sky_summary.observers.<id>.label/file_tag/outputs`；多观测点用 `天空轨迹_<label>_<lat>N_<lon>E`，单观测点仍用 `天空轨迹_<obs_id>`（全景单点=`天空轨迹_全景.png`、多点=`天空轨迹_全景_<label>_<lat>N_<lon>E.png`）；报告与参考样式主图按 `outputs` 实际路径读写，不要再自己拼文件名；
- **重复成果保护（v3.2.3）**：`app/core/workspace.py` 的 `has_results/unique_dir/prepare_workdir` 是 GUI 与 CLI 的唯一判定源——GUI 弹窗「覆盖/新建/取消」，CLI 默认 `renamed`（`_2`）、`--overwrite` 才复用；改判定/提示时两边要同步；
- **可取消**：`should_stop()` 在每步前检查，GUI 的「取消」走 `runner.cancel()`。

## 3. 环境变量（runner 每步设置）

| 变量 | 含义 | 设置者 |
|---|---|---|
| `RK_ENGINE` | 引擎根目录（含 common/ scripts/ data/ne/ viz/files/） | `paths.setup_env()` |
| `RK_ROOT` | 当前任务工作区（config.json 与全部产物） | `runner._apply_env()` |

```jsonc
 "class": "medium_liquid",                 // small_solid / medium_liquid / large_liquid / crewed
 "liftoff_mass_kg": 250660, "leo_kg": 3100, "sso_kg": 1300,
 "default_payload_kg": 1000,
 "typical_orbits": [{"name":"SSO 505","alt_km":505,"i_deg":97.45}],
 "launch_sites": ["ty_lc9"],               // 可选：典型工位 id
 "guidance_defaults": {"t_v":7.764,"t_p":169.075,"pitch_power":1.056,
                       "t_fairing":206.0,"fairing_divert_mps":4.0,
                       "plane_keeping":false,"yaw_tau":150,"i_target_deg":null,"azimuth_deg":null},
 "vehicle": {"adapter_kg":..., "payload_kg":..., "ascent_cda_scale":...,
             "stages":[{"name":"一级","dry_kg":...,"prop_kg":...,"engines":4,
                        "thrust_sl_n":...,"thrust_vac_n":...,"isp_sl_s":...,
                        "isp_vac_s":...,"pitch_end_deg":...,"cda_attached_m2":...}, ...],
             "boosters": null,
             "fairing": {"mass_kg":...,"halves":2,"sep_met":206.0,"cda_m2":...},
             "debris": {"stage_0":{"cda":...,"extra_mass_kg":...},
                        "fairing":{"cda":...,"extra_mass_kg":...}}},
 "confidence": "高", "note": "参数来源与拟合说明",
 "sources": [{"url":"https://...","accessed":"2026-11-23","note":"..."}]}
```

规则：

- `stages` 的级名会参与航警 `stage_hint` 匹配（"一级"/"整流罩"/"助推器"）；
- 多工况发动机用 `phases[].thrusters[]`（`n/thrust_vac_n/isp_vac_s`），单工况用 `engines + thrust_*`；
- 末级关机：已知程序关机写 `seco_met`，否则留 `null`（按推进剂耗尽）；
- **不要**给 `cda_attached_m2` 乱补默认值（缺省=0，擅自补会显著改变阻力与半长轴）；
- 改完跑 `python tests\test_db_validate.py`（校验 schema/字段/量级/来源）。

### 4.2 新增发射工位（`app/data/launch_sites.json`）

```jsonc
{"id":"ty_lc9","name":"太原卫星发射中心 LC-9 工位","aliases":["太原 LC-9","太原9号工位"],
 "lat_deg":38.8632,"lon_deg":111.5896,"alt_m_ellipsoid":1459.0,
 "country":"CN","region":"山西","vehicles":["cz2d","cz4b"],
 "confidence":"高","coord_note":"多源核对说明（含各源差值）","sources":[...]}
```

注意同名场区多工位时的别名设计：v3.2.3 起"只写场区名"会走 `infer.match_site` 的**场区中心代表点**回退（`_site_center`：取该场区全部工位经纬度/海拔平均，`confidence=中`，`coord_note` 注明"不代表具体工位"）；写全工位号仍精确匹配。**不要**给多个工位都加同一个泛性别名（如"太原"）——那会和场区中心规则混淆，也让模糊匹配结果不可预期。

### 4.3 新增城市 / 载荷 / 轨道

- `cities.json`：`{name, province, lat_deg, lon_deg, alt_m, aliases[]}`，观测点与地图用；
- `payloads.json`：`{id,name,aliases[],mass_kg,min_kg,max_kg,confidence,note,sources[]}`；
- `orbits.json`：`{id,name,alt_km,i_deg,type,confidence,note}`。

### 4.4 换模板（`engine/templates/config_cz2d.json`）

模板只在 `tests` 与历史复现里用；v3 正常任务由 `config_build` 生成配置。改模板时要同步 `tests/` 里的引用。

### 4.5 测试库（`tests/fixtures/db`）

精简版内置库，供回归测试用：设置 `RK_APP_DATA=tests\fixtures\db` 即可让 `infer.load_db` 读它（`app/core/paths.py: app_data_dir()`）。写回归脚本时**不要**污染 `app/data`。

## 7. 已知设计权衡（改代码前先读）

1. **反演与性能**：反演用 dt=0.5 的粗口径搜索、最终结果用正式步长复算；DE 关闭 polish，改"方位角粗扫 + DE + 局部精修"。预算越大越准越慢（示例 25 次预算约 47–51 s；20×10 精细预算约 160 s）。
2. **qc 是模块感知的**：未启用的模块对应检查项显示"（未启用，跳过）"并按 PASS 处理；"落点入区"只检查**有对应 stage_hint 区**的残骸对象；无航警时跳过落区/窗口检查；`nearest_zone_id/nearest_dist_km` 允许为空。
3. **predict 需要先试算**：`_step_predict` 会先跑一次 export 生成落点再合成预测区（否则新工作区没有 `sim\落点与射程.csv`）。
4. **残骸类型两遍法**：第一遍按距离猜（体检标注"程序推断"），第二遍 `_step_stagehint` 用试算落点最近匹配成 `stage_hint`+`object_hint`；只改推断值，不动用户手工值；匹配 >500 km 告警。这一步必须在 T0 精化与 invert 之前跑，否则窗口/反演配对会错。
5. **收敛守卫**：`invert.py` 比较最优 vs 标称目标（最优 >200 且 >标称 60% 判未收敛），写 `converged=false`；`runner` 把 config 回退到 `config_initial` 的标称参数并记 `_v3.inversion.reverted=true`，报告 §2.2 置顶警示。**不要**在未收敛时仍用候选参数回填。
6. **通用模板是降级路径**：无箭型时用 `_FALLBACK_ROCKETS["generic_medium_liquid"]`，参数只保证量级；若未入轨，`export` 写 `warning` 字段、报告置顶提示，QC 会 FAIL「入轨根数合理」（这是正确判据，不要改成静默通过）。
7. **dogleg 护栏**：参考轨道倾角与"由方位角反算的倾角"差 <2° 不启用；2–12° 启用；>12° 关闭并给低置信度提示（上升段做不出大平面变化）。
8. **KML 区外落点不失败**：`impactOut/impactOther` 只是可视化区分，`校验_KML.json` 记 `n_impacts_outside` 与 `warnings`；落区判定由 qc/报告负责，KML 步骤退出码保持 0。
9. **DEM 优先 SRTM、缺失回退粗 DEM**：粗 DEM 只保证流程能跑，报告会自动降级声明。
10. **GUI 计算在后台线程**：主线程只用 `queue.Queue + root.after` 刷 UI；取消用 `runner.cancel()`，不要直接 kill 线程。
11. **报告生成两次**：qc 之前先生成（qc 要检查报告存在），qc 之后用自检结果再刷一次（§7 才有内容）。
12. **参考轨道比对规则会改变反演行为（v3.2.3）**：置信度升"中"后（1）可能触发 dogleg（≥2°），（2）autoplan 不再走"低置信放宽"分支。改 `infer_reference_orbit` 的 5°/8° 阈值时，要同步对照 `CHANGELOG_v3.md` 与 03 文档，并重跑真实 CZ-6A 用例（期望：参考轨道 中、700 km/98.2°、dogleg 启用、t_p 区间含标称值）。
13. **无观测点时 map 必须继续跑（v3.2.3）**：`config_build` 只关 sky/appear；`runner._step_map` 不能因 `observers==[]` 跳过；`plot_map.py` 所有"指定观测点"文案要能退化（统计/图例/§4.3/关键地点表/自检）。改这块要回归 `tests\qa\missions\no_observer_map.json`（期望 map PNG 2175×1559、自检 25/25、QC 全国地图 PASS）。
14. **open_path 不要在受限环境 spawn explorer（v3.2.3）**：ShellExecuteW 返回 5 时直接走"剪贴板+提示"；显式启动必须用干净环境（去掉 `_MEIPASS`/`_PYI*` 与 `_internal` 的 PATH 项）+ 绝对路径 + 退出码检测，否则会复现 `0xC0000142`。
15. **天空自检的"最大高度角"必须是可见时段内（v3.2.3）**：掠射观测点（低仰角、地形遮挡角高于几何最大值）会让几何最大值落在可见区间之外；自检只校验"可见区间内 first ≤ last"，几何最大值另列 INFO。回归用例：真实 CZ-2F 5 观测点任务（期望 sky 自检全部通过、QC 26/26；广州点 `basis` 为 `visible_interval`（有 SRTM 时，可见窗口 490.59–506.43 s、可见内 0.48°、几何 0.62° 被遮挡）或 `geometric_only(no_visible_interval)`（粗 DEM 时全程不可见、仅给几何 0.33°），**两种都不允许 FAIL**）。
16. **两遍法告警升级（v3.2.3）**：①原文类型 vs 改判结果不一致 → 显式警告；②最近预测落点 >500 km → 显式警告"该区可能不属于本任务"。两者必须写入 `config._v3.warnings` 且出现在报告「数据体检」；改 `_step_stagehint` 文案时同步 04 文档 §3.8 的实测文本。
17. **多观测点文件名（v3.2.3）**：`plot_sky.py` 负责生成 `file_tag`（地点名+经纬度）并写 `outputs`；**单观测点不要套新命名**（保持 `天空轨迹_<obs_id>`，全景=`天空轨迹_全景.png`），否则既有用户脚本会找不到文件。回归用例：CZ-2F 5 观测点任务（期望 5 套 `天空轨迹_<地点>_<坐标>`；全景/太阳地影/出现方位地形**只对第一个观测点**生成、命名带其地点；无 `_obs1_obs1`）。
18. **重复成果保护（v3.2.3）**：判定只在 `workspace.prepare_workdir`；CLI 默认"新建 `_2`"而不是覆盖（防止误删旧成果），`--overwrite` 才复用。改 GUI 弹窗文案时同步 01/02/04 文档；验收脚本含 2d（重复检查/覆盖）断言。

## 8. 排查问题的入口

| 现象 | 先看 |
|---|---|
| 某步失败 | 工作区 `运行日志.txt` 末尾；`--modules` 缩小到该步单独跑 |
| 配置/推断不对 | `config.json` 的 `mission._provenance`（数据体检原始记录）与 `_v3.warnings` |
| 残骸类型可疑 | 日志「残骸类型校正（两遍法）」；`config.notams[].stage_hint/object_hint`；>500 km 告警 |
| 落点不对 | `sim\落点与射程.csv`（zone_id/inside_zone/dist_to_boundary_km/**nearest_zone_id/nearest_dist_km**）+ `sim\notam_zones.json` + `config.inversion` |
| 反演不收敛 | `sim\反演参数.json`（objective/nominal_objective/converged/bounds/nfev）+ `config._v3.inversion.reverted`；先检查 stage_hint 与多边形 |
| 天空图不对 | `sky\sky_summary.json`（`max_elevation.basis` / `geometric_max_masked` / `max_elevation_geometric`、`dem` 模式、`horizon_deg`、`first_appearance`）；检查 `sky\` 是否只剩本轮文件（有旧产物说明清理没跑） |
| 天空"最大高度角"疑似偏低 | 正常：默认是**可见时段内**口径；对比 `max_elevation_geometric`，若差值大且 INFO 说"落在可见区间之外"，是地形遮挡所致（不是 bug） |
| 残骸类型告警 | `_v3.warnings` 里的"原文残骸类型为…改判为…"/"该区可能不属于本任务"；报告「数据体检」章节；两遍法实测日志 |
| 天空文件名/旧图 | `sky\` 里应有 `天空轨迹_<地点>_<坐标>.*`（多点）或 `天空轨迹_<obs_id>.*`（单点）；`sky_summary.observers.<id>.outputs` 是权威清单 |
| 重复计算/覆盖 | 看启动时 CLI `[提示] 本次自动新建工作区…` / `[提示] 覆盖模式…`；GUI 看状态栏与运行日志里的工作区选择 |
| 地图/KML | `map\统计.json.checks`、`viz\校验_KML.json.checks`（含 `n_impacts_outside`）与 `warnings`；无观测点任务看 map `.md` 的"未指定观测点/发射点代理值"说明 |
| 参考轨道/dogleg 可疑 | `config.mission.reference_orbit.confidence`、`config.guidance.i_target_deg`、`config.mission._provenance` 的"参考轨道"note、`弹道事件表.csv` 是否有"末级平面修正(dogleg)开始" |
| 打开成果/报告/KMZ 失败 | `paths.open_path()` 返回值与提示（是否含"剪贴板"）；受限环境不要 spawn explorer；`%TEMP%` 日志无 `0xC0000142` 即正常 |
| 打包后异常 | `--env` 输出（引擎目录、内置库条数、粗 DEM）；`_internal\` 是否完整 |
