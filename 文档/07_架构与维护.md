## 1. 一眼看全

## 5. 数据流

```text
                 ┌──────────────── GUI（八步页） / CLI（任务 JSON）────────────────┐
                 │ MissionInput（app/core/model.py）                              │
                 └───────────────────────────┬────────────────────────────────────┘
                                             ▼
                          build_config(inp, workdir, dem_resolver)
                     ┌───────────────────────┴─────────────────────────┐
        Resolution 体检单 / gaps / warnings                    config.json
                     │                                              │  config_initial.json
                     ▼                                              ▼  任务输入.json
              步骤 ⑦ 数据体检                                PipelineRunner.run()
                                                                    │
        env → [predict] → [stagehint] → [t0refine] → dem → invert → export
           → station → window → docking → return → sky → appear → map → mc
           → kml → summary → report → qc
                                                                    │
                                                    sim/ sky/ map/ viz/ report/ uncertainty/
                                                                    │
                                        summary（关键节点/阶段/环境/统计/摘要/清单）
                                                                    │
                                           report（技术报告）→ qc（自检）→ 再刷报告/清单
```

关键点：

- **配置是唯一真相源**：每一步都重新读 `config.json`，需要回写时用 `_save_config`（如反演最优点、
  T0 精化、DEM 模式）；
- **`sim/` 是数据契约**：所有下游图件/报告只读 `sim/`，不重新积分；
- **`summary` 与 `qc` 会重入**：`summary` 在正常顺序跑一次、`_finish` 时再用最终台账刷新一次；
  `qc` 之后会再生成一次报告，让 §8 有自检结论。

## 6. 关键约定（改代码前必读）

| 约定 | 具体规则 |
|---|---|
| 航警多边形顺序 | `[latitude, longitude]`（不是 GeoJSON 的 `[lon, lat]`） |
| 时间 | **内部一律 UTC**；显示层再转北京时；`config.mission.t0_utc` 格式 `%Y-%m-%dT%H:%M:%SZ` |
| 来源/置信度 | 每个补全项都要产出 `Resolution(field,label,value,source,confidence,note)`；`source ∈ {user,db,infer,default,derived}`，`confidence ∈ {高,中,低}` |
| 模块开关 | 默认值在 `model.DEFAULT_MODULES`；运行时以 `config._v3.modules` 为准（`config_build` 会就地修正：非载人关 `station/docking`、无平面约束关 `window`、`export` 强制 True） |
| 内置库与用户库分离 | `app/data/*.json` 只读；用户数据只在 `userdb.user_dir()`；合并时用户同 id 覆盖并标 `_shadow_builtin` |
| 元数据 | `config._v3` 存 `app_version/built_at/notams_mode/modules/needs_refine_t0/stage_hints_inferred/profile/mission_type/station_enabled/auto_observer/custom_rocket/ref_orbit_mode/warnings` |
| 编码 | 所有 JSON 读入用 `utf-8-sig`（容忍 BOM），写出用 `utf-8`；CSV 写出用 `utf-8-sig` |
| 路径 | 引擎脚本通过 `RK_ROOT`（工作区）、`RK_ENGINE`（引擎根）、`RK_DEM`（瓦片）、`MPLBACKEND=Agg`、`MPLCONFIGDIR` 定位；不要写死绝对路径 |

## 7. 扩展指南

### 7.1 加一个新模块（步骤）

以加 `foo` 为例，需要改 6 处（缺一处就会「勾了但没跑」或「跑了但没记录」）：

| 文件 | 改什么 |
|---|---|
| `app/core/model.py` | `DEFAULT_MODULES` 加 `"foo": True/False` |
| `app/core/runner.py` | `STEP_NAMES` 加中文名；`run()` 的 `order` 加位置；`handlers` 加映射；实现 `_step_foo()`（返回 `bool`，可调 `self._skip(原因)`） |
| `app/gui/tab_options.py` | `MODULE_GROUPS` 的合适分组里加 `("foo", 标签, "关掉会少什么")`；必要时更新 `PRESETS` |
| `app/core/summary.py` | 在 `EXPECTED_*` 里加产物，或在 `expected_outputs` 里按条件追加 |
| `app/gui/tab_run.py` | 如需描述新文件，加进 `_describe` 的表 |
| `app/core/runner.py::_collect_artifacts` | 把主产物加入清单（用于 CLI 输出与结果展示） |

步骤函数约定：

- **返回 `True/False`**，不要 `sys.exit`；
- 需要跑引擎脚本时用 `self._run_script("name", ["--config", self.config_path])`，退出码非 0 视为失败；
- 取消检查用 `self._check_cancel()`；进度用 `self._advance(key, frac)`；
- 「按条件跳过」用 `self._skip("原因")` 并 `return True`——这样台账记「跳过 + 原因」而不是「失败」。

### 7.2 加一个内置箭型

- 内置库 `app/data/rockets.json` 是**只读**资源：新增条目需要维护 `schema`、`updated`、`sources`
  与 `validate_rocket` 要求的字段；改完跑 `python tests\test_db_validate.py` 与
  `python tests\test_perf_consistency.py`；
- 若要让「新建模板」克隆它，改 `userdb.TEMPLATE_SOURCE`；
- 普通用户加箭型**不需要**动内置库——用编辑器写用户库即可（见 [03](03_自定义箭型.md)）。

### 7.3 加一个引擎脚本

约定（`runner._run_script` 的实现决定了这些约束）：

| 约束 | 原因 |
|---|---|
| 会被**同进程** `runpy.run_path(..., run_name="__main__")` 执行 | 必须提供 `if __name__ == "__main__":` 入口；**不要**在模块级做重活 |
| 参数从 `sys.argv` 取（runner 会临时替换 `sys.argv`，并把 cwd 切到工作区） | 沿用 `argparse` + `--config` |
| 正常结束用 `sys.exit(code)`；0=成功，1=部分失败（仍算成功），其它=失败 | runner 只认 `SystemExit` 的 code |
| 依赖库用 `from common import ...`（`RK_ENGINE` 已在 `sys.path`） | 不要 `sys.path.insert` 到别处 |
| 出图后 `plt.close(fig)` | 同进程反复执行，不关会累积内存 |
| 打印中文进度用 `print` | runner 已把 `sys.stdout` tee 到 `运行日志.txt` |

### 7.4 改界面文案时的同步点

1. `app/gui/help_text.py`（F1 帮助中心，13 主题）；
2. 本 `文档\` 下对应页面（`02`/`03`/`04`/`05`）；
3. 若改了字段名，检查 `app/core/config_build.py` 的 `Resolution.field` 与报告引用。

## 9. 常见坑

| 坑 | 现象 | 对策 |
|---|---|---|
| 引擎脚本同进程执行 | 上一脚本的模块级全局状态污染下一个；重复 import 不重载 | 不要在模块级缓存可变状态；需要时显式 `importlib.reload` |
| `sys.stdout` 被 tee | GUI 里 `print` 不进控制台而进日志（正常） | 需要「真正 stdout」时用保存的引用（`app/main.py` 的 `_REAL_OUT` 做法） |
| cwd 会被切换 | 脚本里相对路径解析到工作区 | 用 `RK_ROOT`/`RK_ENGINE`/`--config` 绝对路径 |
| 冻结态多进程不可靠 | `_jobs()` 在 `P.FROZEN` 时强制返回 1 | 打包版不要指望 MC 并行 |
| matplotlib 后端 | 无显示环境下必须 `Agg` | runner 已设 `MPLBACKEND=Agg`；自写脚本不要 `plt.show()` |
| 中文字体缺失 | 图上中文变方块 | `common.plotstyle.setup()` 会优先用 `msyh.ttc` 等；缺失时改用其它字体文件 |
| BOM | 用记事本另存后 JSON 解析失败 | 读入统一 `utf-8-sig`；DEM 索引也做了 BOM 容错 |
| 编码 | GBK 保存的 config 无法解析 | 一律 UTF-8；CSV 用 `utf-8-sig` |
| 工作区已有成果 | 命令行/界面行为不同（会自动新建 `_2`） | CLI 要复用旧目录必须 `--overwrite` |
| GUI 线程 | tkinter 只能在主线程操作 | 后台线程只通过 `queue` + `after` 回主线程（`main_window._post/_poll`） |
| 模块开关三处不一致 | 勾了没跑 / 跑了没记录 | 按 §7.1 六处同步改 |
| `export` 是必选 | 关掉直接报错 | 不要试图绕过（`config_build` 与 `main_window` 双重校验） |
