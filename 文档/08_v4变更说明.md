# 08 v4 变更说明

## 1. 版本与交付形态

| 项 | 值 |
|---|---|
| 版本号 | `app/VERSION` = **4.0.1**；标题栏跟随 VERSION；`config.mission.version` = `v4.0` |
| 入口 | `python -m app.main`（GUI）／`python -m app.main --cli …`（命令行）／双击 `启动器.bat` |
| 依赖 | 见 `requirements.txt`（numpy/scipy/matplotlib/pillow/pandas/python-docx/sgp4） |
| 打包 | **本版未做应用程序打包**：仓库没有 exe、没有 `build\` 目录、没有 PyInstaller spec，只能源码运行 |
| 配置 schema | 仍写 `_schema = "rocketkit.config.v3"`（**字段名没变**，v4 只在其中新增键，见 §3） |

## 2. v3 → v4 主要变化

| 方面 | v3 | v4 |
|---|---|---|
| 界面骨架 | `ttk.Notebook` 平铺 7 页 | **左侧八步向导 + 右侧步骤页**；顶部常驻任务概要条；底部上一步/下一步 |
| 步骤 | ①任务信息 ②航警 ③观测点 ④运行选项 ⑤空间站 ⑥数据体检 ⑦运行 | ①任务与箭型 ②**轨道与时序** ③航警与落区 ④观测点 ⑤空间站与返回 ⑥输出与模块 ⑦数据体检 ⑧运行与成果 |
| 任务类型 | 隐式（`profile` 自动/standard/cz2f，返回靠开关） | **显式三选一**：常规/载人/返回舱返回（`mission_type`），`auto` 仅在 JSON/CLI 中出现，CZ-2F 自动判载人 |
| 自定义箭型 | 手写 `app/data/rockets.json` | 图形编辑器六页 + 用户库 `user_data\rockets.json`（内置库只读） |
| 参考轨道 | 只能填高度/倾角 | **五种来源**（自动/模板/我的库/手填/TLE）+ 轨道编辑器 + `user_data\orbits.json` |
| 制导参数 | 不可覆盖（全靠反演） | 步骤 ② 可填 7 项覆盖（`guidance_overrides`） |
| 发射时序 | 在「运行选项」页 | 在步骤 ②，带时间轴预览、差值提醒、模板保存/应用 |
| 输出 | 参数留空会导致步骤被跳过、成果变少 | **输出最大化**：新增 `summary` 模块；无观测点时默认用发射场；新产出任务摘要/成果清单/关键节点/飞行阶段/环境剖面 |
| 运行可解释性 | 只有日志 | **步骤台账**（完成/跳过/不适用/未启用/失败/取消 + 原因）写进成果清单与运行页 |
| 快捷键 | 无 | `F5` 计算、`F1` 帮助、`Ctrl+1..8` 跳步、`Ctrl+N/O/S`、`Alt+←/→` |
| 帮助 | README + 旧文档 | 程序内**帮助中心**（13 主题 + 搜索 + 一键打开 `文档\`）+ 本目录 9 篇 |

## 3. 新增的配置字段

`MissionInput`（`app/core/model.py`）新增 9 个字段：

| 字段 | 类型 / 默认 | 写入 config 的位置 | 说明 |
|---|---|---|---|
| `mission_type` | str，`"auto"` | `mission.mission_type`、`_v3.mission_type` | `auto/standard/crewed/return`；GUI 默认 `standard` |
| `custom_rocket` | dict，`{}` | `mission.custom_rocket.{id,name,mode,record}` | 编辑器返回的完整箭型记录 |
| `custom_rocket_mode` | str，`""` | `mission.custom_rocket.mode` | `session`（仅本次）/ `user_db`（已存库） |
| `ref_orbit_mode` | str，`"auto"` | `_v3.ref_orbit_mode`、`mission.reference_orbit_mode.mode` | `auto/template/user/custom/tle` |
| `ref_orbit_name` | str，`""` | `mission.reference_orbit_mode.name` | 模板名或我的轨道名 |
| `ref_orbit` | dict，`{}` | `mission.reference_orbit`（经 `resolve_user_reference_orbit` 归一） | 手填：`alt_km/i_deg/e/raan_deg/argp_deg/ltan_h/epoch_utc/type/name` |
| `ref_orbit_tle` | str，`""` | 解析后写入 `mission.reference_orbit` | TLE 原文 |
| `auto_observer` | bool，`True` | `_v3.auto_observer`（=用户设置）、`_v3.auto_observer_used`（=本次是否真的用了）、`mission.auto_observer`（仅真的用了才写） | 无观测点时用发射场 |
| `guidance_overrides` | dict，`{}` | `guidance.*`（并记 `_provenance` 来源=user） | 界面提供 7 个键：`t_v/t_p/pitch_power/azimuth_deg/i_target_deg/yaw_tau/fairing_divert_mps`；`mission_input_from_config` 回环还认 `seco_band_km`/`seco_e_max` |

模块开关：`DEFAULT_MODULES` 新增 **`summary`**（通用成果汇总，默认 `True`），模块总数 **14 → 15**。

`config._v3` 新增/明确：`mission_type`、`auto_observer`、`auto_observer_used`、`custom_rocket`（bool）、
`ref_orbit_mode`、`station_enabled`、`profile`；`config.mission` 新增 `mission_type`、`custom_rocket`、
`reference_orbit_mode`、`auto_observer`（仅在实际使用发射场作观测点时出现）。

返回任务的 config 结构不同（`_build_return_only_config`）：

| 键 | 返回任务时 |
|---|---|
| `return_only` | `true` |
| `mission.profile` / `mission.mission_type` | `return` / `return` |
| `vehicle` / `guidance` / `grid` / `dem` | **不存在**（不看箭型、不算上升段） |
| `observers` | `[]` |
| `station` / `return_capsule` | 必填（返回段依赖） |
| `_v3.modules` | `dem/invert/export/window/sky/appear/mc/docking = false`；`station/return = true`；`kml/report/qc` 跟随用户勾选 |

## 4. 兼容性

### 4.1 旧任务 JSON（v3 导出的 `MissionInput`）

| 情况 | 结果 |
|---|---|
| 缺 `mission_type` | `grab` 到默认 `"auto"` → 按 `profile` 或箭型识别（CZ-2F → 载人；`profile=return` → 返回） |
| 缺 `auto_observer` | 默认 `True`（无观测点时自动用发射场） |
| 缺 `custom_rocket` / `ref_orbit_*` | 走原有推断路径 |
| 缺 `guidance_overrides` | 空 dict，不覆盖 |
| 缺 `launch_sequence` | 空 dict = 全用箭型默认 |
| 多出未知字段 | `MissionInput.from_dict` 只取已知字段，多余字段被忽略（不报错） |

### 4.2 旧 `config.json`（v3 工作区的配置）

界面「打开任务 JSON…」与 CLI `--mission` 都能直接吃完整 config：识别特征是同时含
`mission` 与 `vehicle` 两个键 → 走 `mission_input_from_config` 反推输入。

| 反推项 | 来源 |
|---|---|
| 任务名/箭型/遥号/工位坐标 | `mission.name/rocket/serial/launch_site` |
| T0 | `mission.t0_utc` |
| 航警 | `notams[]`（id/b/c/q/fir/polygon/stage_hint/verified/raw_text） |
| 观测点 | `observers[]` |
| 模式 | `numerics.mode` |
| 任务类型 | `mission.mission_type` 或 `_v3.mission_type` 或 `"auto"` |
| 自定义箭型 | `mission.custom_rocket.{record,mode}` |
| 参考轨道来源 | `_v3.ref_orbit_mode` 或 `mission.reference_orbit_mode.mode`；`custom/tle` 时把 `mission.reference_orbit` 放回 `ref_orbit` |
| 制导覆盖 | **从 `mission._provenance` 反推**：`field` 以 `guidance.` 开头且 `source=user` 的项 → `guidance_overrides` |
| 发射时序 | `launch_sequence` 原样带回（嵌套/扁平都认） |
| 空间站/返回段 | `station.*`、`return_capsule.*` |

已知限制（反推是「尽力还原」）：

- 观测点被程序自动补的发射场观测点也会被读成普通观测点，再次运行不会重复添加，但语义上从
  「自动」变成了「用户给定」；
- 反演回填后的 `guidance` 与原始覆盖值无法区分，只能按 `_provenance` 的 `source=user` 判断；
- `auto_observer` 若旧 config 没写，默认 `True`。

### 4.3 旧工作区能否直接重跑

可以：直接用旧工作区目录重跑（CLI 加 `--overwrite`），v4 会用旧 `config.json` 反推输入、
生成新的 `config.json`（覆盖旧文件）并补齐 v4 新增的通用成果。旧的 `sim/` 文件会被新结果覆盖。
建议先备份或在「新建副本」模式下跑。

## 5. 修复清单

| # | 问题（v3） | v4 处理 | 证据文件 |
|---|---|---|---|
| 1 | 自定义时序里的抛罩时刻丢失（`guidance.t_fairing` 没被写回） | 自定义时序应用后显式写回 `guidance["t_fairing"] = 抛罩秒数` | `app/core/config_build.py::_apply_launch_sequence` |
| 2 | `_jobs()` 一串互相抵消的分支，永远返回 1（用户设 `jobs>1` 被吞） | 按「用户显式值 > `RK_FORCE_PARALLEL` > 串行」生效；冻结态强制 1 | `app/core/runner.py::_jobs` |
| 3 | 返回任务的模块门控混乱（上升段模块名义上开着） | 返回任务走独立构建分支，明确关闭上升段模块，并在台账记「不适用 + 原因」 | `config_build._build_return_only_config`、`runner.run()` 的 `not_applicable` |
| 4 | DEM 相关 JSON 带 BOM 时读取失败 | 运行时读取自定义高程索引统一 `utf-8-sig`；索引损坏时由导入器备份成 `index.json.bad-<时间戳>` 后重建，不崩溃 | `engine/common/dem.py`（读 `custom/index.json`）、`app/core/dem_import.py::load_index` |
| 5 | 用户库/JSON 带 BOM 时解析失败 | `_read_json_tolerant` 与各处 `json.load` 统一 `utf-8-sig` | `app/core/userdb.py`、`app/core/summary.py`、`app/core/runner.py` |
| 6 | 从历史 config 载入时，嵌套 `launch_sequence.values` 里的自定义值丢失 | `_apply_launch_sequence` 同时支持扁平与 `{custom, values:{…}}` 两种结构 | `app/core/config_build.py` |
| 7 | 飞行环境（动压）用了惯性速度，动压偏大 | 新增 `_air_relative_speed`：按相对气流速度（扣除地球自转）算动压 | `app/core/summary.py` |
| 8 | `widgets.field()` 把控件塞进非父容器，输入框不显示 | 强制以内部 `box` 为父容器构建控件 | `app/gui/widgets.py::field` |
| 9 | 步骤被跳过时只有一句日志，看不出原因 | 新增 `_skip(原因)` 与六态台账（完成/跳过/不适用/未启用/失败/取消），写进成果清单与运行页 | `app/core/runner.py`、`app/core/summary.py`、`app/gui/tab_run.py` |
| 10 | 参数留空导致探索性跳过（无观测点 → 天空类成果全没） | 新增 `auto_observer`；无观测点时默认用发射场，体检标注来源=自动推断 | `app/core/model.py`、`config_build.py` |
| 11 | 参考轨道只能填两个数 | 五种来源 + 轨道编辑器（`dialog_orbit.py`）+ 用户轨道库 | `app/gui/dialog_orbit.py`、`app/gui/tab_vehicle.py` |
| 12 | 自定义箭型必须改内置库 | 箭型编辑器 + 用户库 + 校验/指标预览 | `app/gui/dialog_rocket.py`、`app/core/userdb.py` |

## 6. 迁移指南

### 6.1 普通用户（从 v3 升级）

1. 备份旧工程与成果目录；
2. 安装依赖（`python -m pip install -r requirements.txt`）；
3. 启动 `python -m app.main`，界面上直接「打开任务 JSON…」选旧的 `任务输入.json` 或 `config.json`；
4. 核对三个新东西：**任务类型**（v4 默认「常规发射弹道」）、**参考轨道来源**（默认自动推断）、
   **输出与模块**（建议先「标准（推荐）」）；
5. 生成体检 → 开始计算；先看 `report\任务摘要.md` 与 `report\成果清单.md`；
6. 旧的界面操作记忆需要更新：**发射时序不在「运行选项」了，在步骤 ②**；
   自定义箭型**不要**再改 `app/data/rockets.json`。

### 6.2 维护者

| 事项 | 动作 |
|---|---|
| 旧脚本调用 `app.core.config_build.build_config` | 签名未变（`inp, workdir, logger, dem_resolver, write`），可直接用 |
| 旧脚本读 `config["_v3"]["modules"]` | 键名未变，只是多了 `summary`；旧代码若按「必须全是已知键」校验需要放行 |
| 依赖 `_jobs()` 返回 1 的行为 | v4 会按用户设置返回 >1（冻结态仍 1）；MC 相关性能测试需复核 |
| 依赖 `launch_sequence` 扁平结构 | 两种结构都支持；新代码建议直接读 `values` |
| 自定义箭型读写 | 改用 `app.core.userdb`（`list_rockets/save_rocket/...`），不要再直接改 `app/data/rockets.json` |
| 前端页面对象 | v3 的 `self.tab_xxx` 已统一为 `self._pages["key"]`（key 见 `main_window.STEPS`） |
