# 05 输出成果清单

一次成功运行会在工作区里写出 **60 个左右文件**。本篇按目录说明每个产物是什么、谁生成的、
什么口径；再给三类任务的「应有产物对照表」，最后讲怎么用「输出完整性核对」和「步骤台账」
定位缺失项。

> 约定：路径都是相对工作区根目录。CSV 一律 **UTF-8 with BOM**（Excel 双击不乱码），
> JSON 一律 UTF-8，日志为 UTF-8。

## 1. 目录总览

```text
<工作区>\
├─ config.json / config_initial.json / 任务输入.json / 运行日志.txt
├─ sim\           弹道与事件的「数据契约」，下游所有图件与报告都读它
├─ sky\           观测点视角的天空轨迹与数据
├─ map\           全国可见性地图、晨昏线、落区图
├─ viz\           三维 KML/KMZ
├─ report\        报告、任务摘要、成果清单、交付自检、发射窗口
├─ uncertainty\   蒙特卡洛（启用 mc 时才有内容）
└─ 数据体检\       预留目录（环境准备步骤创建，当前版本不写内容）
```

## 2. 根目录

| 文件 | 生成者 | 用途 / 口径 |
|---|---|---|
| `config.json` | `config_build.build_config`（生成），`runner` 各步回填 | 本次运行**最终**配置：`mission` / `vehicle` / `guidance` / `numerics` / `notams` / `observers` / `grid` / `dem` / `launch_window` / `station` / `return_capsule` / `launch_sequence` / `inversion` / `_v3`（含 `modules`、`warnings`、`mission_type`、`auto_observer`、`auto_observer_used`、`stage_hints_inferred`） |
| `config_initial.json` | 同上（写盘时同时存一份） | 反演**之前**的初值，用来核对反演改了哪些参数 |
| `任务输入.json` | 界面（开始计算/一键写入）或 CLI | 原始输入（`MissionInput`），复现与「打开任务 JSON」用 |
| `运行日志.txt` | `runner` | 带时间戳的完整日志（控制台里看到的一切） |

## 3. `sim\` —— 弹道与事件

### 3.1 由 `engine/scripts/export.py` 生成（数据契约）

| 文件 | 内容 / 口径 |
|---|---|
| `trajectory.csv` | 弹道时间序列（0.5 s 步长）：`t`、UTC、经纬高、速度、质量、`phase` 等 |
| `debris_trajectories.csv` | 残骸下落轨迹（1 s 步长），每个残骸对象一段 |
| `弹道事件表.csv` | 事件表：起飞/点火/分离/抛罩/关机等，含时刻与状态 |
| `落点与射程.csv` | 每个残骸对象的落点经纬度、射程、落点时刻（**落区判定的输入**） |
| `入轨根数.json` | SECO 时刻瞬时根数：`a_km` / `e` / `i_deg` / `perigee_km` / `apogee_km` / `period_s` |
| `orbit_track.csv` | 入轨后约 1.5 圈星下点轨迹 |
| `objects.json` | 残骸对象清单（名称、类型提示、是否入区等） |
| `notam_zones.json` | 解析后的危险区多边形（含预测区，标注是否推断） |
| `trajectory_meta.json` | 元数据：T0、站点、制导参数、`insertion_t_met_s`、数据来源 |

> `export.py` 还有一个 `--params` 参数，默认读 `sim\nominal_params.json`（由 `invert` 生成）
> 作为制导参数来源；没有反演时用 `config.guidance`。

### 3.2 由反演 / 通用汇总 / 专业模块生成

| 文件 | 生成模块 | 内容 / 口径 |
|---|---|---|

| `飞行环境.csv` | `summary` | 动压与过载剖面：`q_pa`、`accel_g`、高度、速度、质量（**按相对气流速度算动压**） |
| `飞行环境关注项.json` | `summary` | 载人与飞行环境关注项（过载/动压与参考限值对比、结论）；有超限项才写 |

| `交会对接.json` | `docking` | 入轨+交会方案：相位调整、Hohmann、末段逼近、总 ΔV、预计对接时刻；`docking` 内含对接点星下点，`plane` 内含实测入轨面残差 |

| `返回舱返回.json` | `return` | 返回窗口、选中弹道、再入峰值、落点、1σ 散布 |
| `返回舱_时序.csv` | `return` | 返回时序：制动/再入/开伞/着陆 |
| `返回舱阶段.csv` | `return` | 返回阶段划分与时长 |
| `返回舱事件与分离点.csv` | `return` | 返回关键事件与（轨道舱/推进舱）分离点 |

## 4. `sky\` —— 观测点天空轨迹

| 文件 | 内容 |
|---|---|
| `天空轨迹_<观测点>.png` | 主图：方位角–高度角天空轨迹 + 可见性时间轴 + MET 色条 |
| `天空轨迹_<观测点>.csv` | 逐时刻方位/高度/距离/可见性数据 |
| `天空轨迹_<观测点>.md` | 图说明：数据来源、DEM 模式、方法、可见性统计、局限 |
| `天空轨迹_全景_<地点>.png` | 全景（不裁剪地平线以下部分） |
| `太阳地影示意_<地点>.png` | 太阳与地影对观测的影响示意 |
| `出现方位地形_*.png` | 出现方位地形判读图（`appear` 模块） |
| `出现方位地形_数据*.json` | 上述图的数据（`appear` 模块） |
| `sky_summary.json` | 天空轨迹汇总：每个观测点的首次出现/最大仰角/方位/可见时长，`appear` 与报告都读它 |

多观测点时文件名带「地点名 + 纬度 + 经度」，例如
`天空轨迹_太原_37.76N_112.72E.png`；单观测点用观测点 id（如 `天空轨迹_obs1.png`）。
参考样式主图会**覆盖**同一张主图 PNG（`plot_sky_refstyle` 重绘），不额外产生新文件名。

## 11. 「输出完整性核对」怎么读

出现位置（三处同一份数据）：

1. `report/成果清单.md` §2：每行「分组 | 文件 | 说明 | ✔已产出 / ✘缺失」；
2. `report/任务摘要.md` §6：把缺失项列出来，并指向成果清单的步骤台账；
3. 步骤 ⑧ 运行页「成果文件」顶部提示：`共 N 个文件 / 体积；应产出缺失 M 项`。

判断流程：

| 现象 | 含义 | 下一步 |
|---|---|---|
| 缺失项为 0 | 表内应产出项都在 | 再跑 `qc_report.json` 看内容质量 |
| 缺失 `sky/*` | `sky`/`appear` 被跳过或失败 | 看台账里这两步的状态与原因：多半是无观测点或 DEM 问题 |
| 缺失 `map/*` | `map` 未勾选或 `plot_map` 失败 | 勾上模块重算，或看日志中 `plot_map` 段落 |
| 缺失 `report/发射窗口计算.json` | `window` 被跳过（无航警且无平面约束） | 提供航警，或在步骤 ② 填 RAAN/LTAN |
| 缺失 `viz/*.kmz` | `kml` 未勾选，或返回任务（正常） | 返回任务本就由 `return` 生成 `返回舱弹道.kmz` |
| 缺失 `uncertainty/*` | `mc` 未启用 | 勾 `mc` + 填样本数 |
| 缺失 `sim/trajectory.csv` 等上升段数据 | `export` 失败 | 这是**关键步骤**，失败会中止后续；看日志最早一处错误 |

## 12. 「步骤台账」怎么读

出现位置：`report/成果清单.md` §1、步骤 ⑧ 运行页「步骤台账」表、`report/任务摘要.md` §6
（只列非完成项）。

六个状态（`runner.PipelineRunner.ST_*`）：

| 状态 | 谁写的 | 含义 | 处理 |
|---|---|---|---|
| 完成 | 步骤正常返回 | 一切正常 | — |
| 跳过 | 步骤内调用 `_skip(原因)` | 依赖不满足，但**不算失败** | 读「说明」补数据 |
| 不适用 | 步骤计划预先判定 | 与任务类型无关（返回任务不做上升段反演等） | 不用管 |
| 未启用（未勾选模块） | 模块开关关闭 | 你没勾 | 需要就勾上重算 |
| 失败 | 异常或非零退出码 | 该步出错 | 看 `运行日志.txt` 里该步骤段落 |
| 取消 | 用户点取消 | 主动中止 | 已生成文件保留，可重跑 |

定位缺失项的三步法：

1. 在成果清单 §2 找到缺失文件所属**模块**（`sky`/`map`/`window`…）；
2. 在 §1 台账找该模块对应行，读状态与「说明」；
3. 若状态=失败，去 `运行日志.txt` 搜该步骤的中文名（如「天空轨迹」），
   错误堆栈紧跟在 `=== 天空轨迹（详细+主图） ===` 之后。
