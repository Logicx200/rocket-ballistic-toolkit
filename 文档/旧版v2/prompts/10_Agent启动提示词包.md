# Agent 启动提示词包（v2，分阶段 / 每段有停靠点）

> 与 `00_给新agent的开场提示词.md` 的区别：00 是「一次性开场」，本文件是**可分阶段执行**的版本，
> 每段都要求 agent「先输出、再停、等确认」，避免它一口气跑完却把假设写错。
>
> 用法：把 §0 的变量填好，按 **P0 → P1 → … → P6** 顺序粘贴；中断后用 **P7** 续跑。
> 所有 `{{...}}` 都是占位符；`<TOOLKIT>` 指工具箱根目录（默认 `F:\DeepSeek工作区\火箭弹道工具箱_v2.0`）。

---

## 0. 变量表（粘之前先填）

| 变量 | 含义 | 示例 |
|---|---|---|
| `{{TASK}}` | 任务名 | 2027-xx-xx 长征x号 太原 LC-x 上升段仿真 |
| `{{ROCKET}}` | 箭型/级数/助推器 | 两级串联、无助推器（或"待查"） |
| `{{SITE}}` | 发射场名称/经纬度/椭球高 | 太原 LC-9 / 38.8632N / 111.5896E / 1459 m |
| `{{T0}}` | 起飞时刻 UTC | 2026-11-18T22:50:00Z（北京时 11-19 06:50） |
| `{{NOTAMS}}` | 航警编号 + B)/C) + 多边形 | A5897/26, 22:43–23:05Z, 4 点… |
| `{{OBS}}` | 观测点 | 37.761467N / 112.725219E / 840 m（或"无"） |
| `{{REF_ORBIT}}` | 参考轨道 | 505 km / 97.45°（或"无"） |
| `{{LEVEL}}` | 交付级别 | A=弹道+落点；B=+天空+地图；C=全套（默认） |
| `{{WORKDIR}}` | 新任务工作区 | `F:\DeepSeek工作区\{任务名}_工作区` |

## P0 开场：角色、边界、先读后答

```
你是一名航天弹道与科学可视化工程师。请用「火箭弹道预报通用工具箱 v2.0」完成一次
上升段 3-DOF 弹道仿真与预报。

工具箱（只读，不要修改）：<TOOLKIT>
任务工作区（所有产物写这里）：{{WORKDIR}}

硬性边界：
- 仅供公开信息分析与教学使用，禁止把它包装成任何实际发射弹道情报。
- 不编造数值：每个关键数字都要能指到脚本输出或公开 URL（含访问日期）。
- 时间一律 UTC 与北京时（UTC+8）双写；坐标 WGS-84；高度注明椭球高/正高。
- 先问后算：任何"无法从公开信息确定"的项，先列出来问我，不要自己假设后直接跑。
- 不要动 <TOOLKIT> 里的文件；需要时复制到工作区再改。

现在只做三件事，**不要开始计算**：
1) 读 <TOOLKIT> 的 README.md、交付说明.md、prompts/02_执行SOP.md、
   prompts/05_数据契约.md、prompts/09_换任务SOP_已知航警.md；
2) 复述我接下来给你的任务卡（P1），并列出你判断的「信息缺口 / 冲突项 / 风险」；
3) 给出你的执行计划（≤8 步），每步写明：命令、产物、验收判据、需要我确认的点。

输出完就停，等我确认。
```

## P1 任务卡（把已知信息填进来）

```
【任务卡】
- 任务：{{TASK}}
- 箭型：{{ROCKET}}
- 发射场：{{SITE}}
- T0：{{T0}}
- 航警：{{NOTAMS}}
- 观测点：{{OBS}}
- 参考轨道：{{REF_ORBIT}}
- 已知参数来源：{{链接/文档/旧工程}}
- 交付级别：{{LEVEL}}
- 禁止事项：不改动旧工程；不混合不同数值口径；不把"未确认"写成"已确认"。
```

## P2 资料检索与核对（产出"有来源的底稿"）

```
按 P1 的缺口做公开检索，只做资料与核对，不改代码、不跑仿真。

要求：
1) 航警：拿到原文（编号/B)/C)/Q 行/多边形顶点），记录来源 URL 与访问日期；
   与用户给的信息逐字核对，差异要列出来。
2) 时间：T0 的公开来源（官方预告/发射场公告/网站列表），标注置信度；
   若只有"标称"，在配置的 t0_note 里写明。
3) 发射场：经纬度至少两源交叉（GE/维基/AeroPattern），给出差值。
4) 箭型：级数、推力/比冲、推进剂/干重、整流罩、是否带助推器；来源与置信度。
5) 观测点：与用户坐标核对（GE 截图/多源），差异 >100 m 必须问。
6) 若航警几何推出的倾角与公开参考轨道差 >0.5°，两个方案都保留并说明。

输出（写到工作区）：
- sources/来源清单.md：表格「项目 / 数值 / 来源URL / 访问日期 / 置信度」
- report/数据缺口.md：未确认项 + 建议取值 + 影响
- 在对话里给一张「关键参数一页纸」：T0、发射场、各级参数、航警多边形、观测点、参考轨道

输出完就停，等我确认关键项（尤其多边形顺序、T0、观测点）。
```

## P3 配置落地（config.json）

```
把 <TOOLKIT>/templates/config_cz2d.json 复制到 {{WORKDIR}}/config.json，按以下规则填：

1) mission：name/rocket/serial、t0_utc（带 Z）、launch_site（经纬度+alt_m_ellipsoid）、
   reference_orbit（没有就整块删掉）、t0_note/coord_note 写来源与置信度。
2) notams：每区一条；polygon_latlon 必须是 [lat, lon]；b_utc/c_utc 要覆盖对应残骸到达时刻；
   stage_hint 用「一级 / 二级 / 整流罩」这种能与级名匹配的词。
3) vehicle：按 prompts/07 填；多工况（主机+游机）用 phases；抛罩可只写 vehicle.fairing.sep_met。
   未知参数用同类箭型估值并加 "_confidence" 字段，不要留空。
4) guidance：azimuth_deg 初值取「发射场→一级航警区质心」的方位角；t_v/t_p/pitch_power 给初值。
5) numerics：保持 {"mode":"accurate","dt":0.2,"dt_legacy":0.02,"sample_dt":0.5,
   "debris_dt":1.0,"debris_mode":"accurate"}。
6) observers：按 P1；没有观测点就删掉该块（天空轨迹那步会跳过）。
7) 可选：inversion（参数与边界必须按本任务设）、mc、window。

自检（必须做，逐条报结果）：
- python -c "import json;json.load(open('config.json',encoding='utf-8'))"
- 每个 notam 的 stage_hint 都能匹配到级名或"整流罩"
- B)/C) 时长 ≥ 残骸飞行时间（否则 window 会无解）
- seco_met 与 prop_kg 不矛盾（二者只能一个决定末端）

输出：config 字段摘要表（字段/值/来源/置信度）+ 与模板的差异清单。停，等我确认。
```

## P4 粗跑与反演（率定落点）

```
目标：让各残骸落点落进对应航警区，并让入轨根数接近参考轨道。

1) python scripts\export.py --config config.json
   读 sim\落点与射程.csv、sim\弹道事件表.csv、sim\入轨根数.json，判断参数是否离谱：
   - 落点差 10–100 km：正常（还没反演）
   - 差 >500 km 或飞不出去：先查方位角方向、推进剂量级、t_p/pitch_end 符号、级数/分离时刻
2) 按本任务改 config.inversion.parameters 的边界（默认是 CZ-2D 的值，必须改）。
   未知量优先级：azimuth → t_v/t_p/pitch_power → t_fairing → seco_met。
3) python scripts\invert.py --config config.json --jobs 8 --maxiter 20 --popsize 10
   （要快用 --quick；要与旧版数字对齐用 --legacy——但**必须与最终导出口径一致**）
4) 把最优点回填 config.json，再跑一次 export 确认落点入区；
   记录反演目标值、迭代数、落点表。

输出：落点表（对象/经纬度/是否入区/距边界 km）、入轨根数 vs 参考轨道、反演参数表、
口径声明（legacy 或 accurate）。停，等我确认。
```

## P5 全流程执行（一条命令）

```
执行前先确认：DEM 是否就绪（{{WORKDIR}}/data/dem/hgt 非空）。
- 未就绪：python scripts\fetch_dem.py --config config.json
  （网络慢时可先跳过，天空轨迹会退化为平地 −0.1°，必须在报告里标注"非正式"）

然后：
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_all.ps1 -SkipDem -MC 250 -Jobs 8 -SkipAppear

说明：
- -SkipAppear 用于换任务：出现方位判读图带本任务定制常量，除非我已让你改常量；
- 失败时：按报错单独跑该脚本（加 --help 看参数），不要整段重跑掩盖问题；
- 产物写在工作区的 sim/ sky/ map/ viz/ uncertainty/ report/。

输出：每步 OK/失败、耗时表、产物存在性（文件/大小）。停。
```

## P6 验收与报告

```
1) python scripts\qc.py --config config.json
   对每个 FAIL：给原因、修复方案、是否可接受（唯一允许的固定 FAIL 是"报告未撰写"）。
2) 按 prompts/06_自检与验收清单.md 逐项过 DoD，重点：
   落点入区且距边界 >1–2 km、落点时刻在航警有效期内、窗口时长 >0、
   入轨 e<0.05 / 150<h<2000 km / P>4000 s、天空轨迹首现/最大/消失单调。
3) 写 report\弹道仿真报告.md（≥12 章，按 prompts/01 §二 清单，内嵌全部图、所有数值可追溯），
   必须含：假设、模型、反演与多解性、验证、精度与局限、来源、免责声明。
4) 最终回复我一张表：事件时刻 / 落点与余量 / 入轨根数 / 观测点可见性 / 窗口；
   再列：产物清单、剩余不确定项、下一步建议。
```

## P7 断点续跑 / 交接

```
上一个 agent（或上一轮）中断了。先恢复状态，不要重跑已完成阶段：
1) 读 report/进度.md（没有就看 sim/ sky/ map/ uncertainty/ 的产物与时间戳）；
2) 告诉我：已完成到哪一步、当前数值口径（legacy/accurate）、config 的 T0/落点数字；
3) 给出"下一跳"的具体命令，以及它依赖哪些前置产物；
4) 我确认后再执行。
```

## 附：常见"跑偏"与纠正提示词

| 现象 | 贴给 agent 的一句 |
|---|---|
| 编造参数 | `把所有无来源的数字列出来，逐个标"未确认/来源"，未确认的不许进 config` |
| 跳过反演 | `落点未入区就出图没有意义；先按 P4 率定并给我落点表` |
| 口径混用 | `声明你用的 numerics.mode，反演与导出必须是同一口径；不一致就重跑` |
| 多边形写反 | `检查 notam 多边形是 [lat, lon]；用第一个顶点反算经纬度范围，落在该航警 FIR 内才算对` |
| 忘记任务定制脚本 | `你改过 make_kml_refstyle.py 里的 T0/ZONES 吗？没改就加 -SkipKml 或先改常量` |
| 一口气跑完不报告 | `从现在起每阶段结束先输出"产物+关键数字+下一步"，等我确认再继续` |
